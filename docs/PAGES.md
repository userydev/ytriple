# 页面职责与路径设计

统一确认入口：[UI 与交互确认稿 v1](UI-BASELINE.md)。本文保留对应领域的详细规则。

2026-09-16 关系重整版。依据 [PRODUCT.md](PRODUCT.md) 与 [INTERACTION.md](INTERACTION.md)。实现覆盖与现场验证见 [交付记录](DELIVERY.md)；旧 24 张视觉稿是候选素材，不是必须逐页实现的清单。

## 先决定对象，再决定页面

页面只回答当前用户的一个主要问题。跨页靠同一工作、成果版本与引用连接；不靠在每页复制聊天框、待办和成果卡来“打通”。对象创建、动作副作用和状态转换以 INTERACTION 为准，本文不另定义第二套规则。

| 层次 | 包含什么 | 展开条件 |
| --- | --- | --- |
| 全局入口 | 首页、雷达、项目、资产；定时任务直接可达，设置辅助 | 用户选择工作领域 |
| 对象页 | 解读、项目、成果、资产、委托 | 阅读或管理一个明确对象 |
| 具体工作 | 同一工作的轻对话、双区协作、三面自由排列 | 发送目标或继续已有工作；切视图不运行 |
| 局部配置 | 来源管理、团队搭配、流程、引用选择、版本历史 | 用户正在处理相关对象；不与主要内容并列铺开 |

雷达保持独立阅读逻辑，项目保持持续目标与交付逻辑。不能为了减少页面把两者都塞进聊天，也不能把一次局部配置升级成新的业务领域。

## 首页：决定从哪里进入

首页保留亮色、左侧汉堡导航与底部明显输入。主要内容是“继续工作”和有实质内容的“雷达观察”，雷达权重不降低。丰富度来自内容，不来自额外状态模块。

- **继续工作**按工作组织：名称、项目/交付归属、一句实质变化、准确成果入口。用户固定优先，其次本人最近使用；不凭模型猜测重新排序。
- **需要决定**附在对应工作行里。若必须先处理某个待决，“查看待决”替代该行的主行动，而非另外再放“继续”“处理”“进入三窗口”三个同级按钮。其他动作在进入后可达。
- **雷达观察**用一条重点解读和若干短解读承接直接阅读，标题、正文摘要、来源覆盖及与工作有关的具体原因；点击进入同一解读。没有依据不硬凑项目关联。
- **底部输入**默认明确写“新工作”，发送开始新目标；直接可见的工作区图标用于展开同一草稿。它不能悄悄续上当前高亮工作。点击继续后才进入标有工作名称的轻对话。
- 首页查找可到达全部工作，包括未归入项目的工作。

移除独立的“团队最近做了什么”、最近成果、一般待补材料及健康面板。这些内容在原工作可见，首页只显示足以决定下一步的变化。成果片段可作为重点工作的一部分，但不在旁边另复制同一脚本卡。打开轻对话后只保留当前工作输入，退出恢复首页的新工作入口。

## 雷达：先理解，再决定是否开展工作

列表的主动作是阅读；收藏和筛选是轻动作。来源与订阅从管理入口进入，不与文章争同等版面。详情正文优先，依据在原文引用或按需展开的来源区；没有必要常驻证据、话题、项目、推荐四列。

正文后提供“围绕这篇解读开展工作”入口，点击后展开唯一的底部输入，清楚显示新工作及解读版本。关闭输入保存草稿并恢复阅读；再次进入同一解读版本恢复该草稿。发送前不建立工作；发送后进入具有名称的轻对话。已有相关讨论通过“相关工作”列表到达，各个目标分开，不因引用同一篇文章就自动合并。

保存、关联项目不调用团队。关联只加引用，不能表示已授权读取整个项目。来源变更保留旧引用并提示复核；返回解读保持滚动和筛选。未读全文显示实际覆盖，来源失败不伪装无更新。

“整理议题 / 检查更新”是明确的内容处理动作，与阅读和收藏分开。用户能检查所选材料及保留/排除理由；仅保存筛选规则不调用模型。检查使用所选范围，输入未变化复用已有成功检查，无新的实质理解不重复生成文章。解读版本和来源版本可追溯；失败保留上次可读解读，不把失败显示为无更新。自动订阅处理只有在相应委托明确启用后执行。

## 项目：交付组织工作

### 项目列表

每项呈现持续目标、当前交付和必要状态，主动作是打开概览。新建/导入是列表工具，不在每个项目再复制一组聊天入口。新建先名称、类型、目标，导入再选择范围；不能把目录存在叫作已理解。

### 项目概览

项目页回答“正在交付什么，下一步推进哪里”。目标与已采纳标准以短摘要呈现，详细标准、正式资料和反馈在局部入口中。

当前交付是主要阅读单位：交付目标、采用版本或暂无采用版本、最近实质变化、相关工作。选择明确的工作后显示“继续：工作名称”的输入与展开入口。多个工作无法确定时先显示工作选择，不根据最新消息自动替用户选定。

“开始另一项工作”是明确的次级动作，会把输入标为新工作并保存原草稿。项目对话不作为与交付工作平行的万能线程。没有交付时允许先围绕目标开展工作，之后再关联交付，不强迫先做管理配置。

| 语义 | 媒体项目 | 软件项目 |
| --- | --- | --- |
| 长期目标 | 频道、受众与已采纳表达标准 | 产品目标与已确认边界 |
| 交付对象 | 一条作品；可能含脚本和制作说明 | 一个版本或明确交接目标 |
| 当前工作 | 选题、脚本修订、反馈复盘等真实目标 | 需求讨论、范围取舍、交接检查等真实目标 |
| 使用证据 | 实际发布或导入反馈 | 实际交接、外部开发或回验记录 |

不新增永远占满首屏的表达标准、项目材料、团队活动与下一步卡片；它们出现在相关交付或按需打开。运行成功不自动改变交付完成状态。

### 资料与成果

资料列表区分原始材料、正式资料、引用与草稿，选择后预览准确内容和覆盖。选择/浏览不触发扫描或上传；所选资料只有加入工作输入才成为本轮候选上下文。

成果详情是同一个成果阅读器，可从项目、工作、资产打开。默认显示入口指定的版本，清楚标示是否有更新版本；不按最新版本强行覆盖项目采用版本。正文是主角，历史、依据和导出为局部工具。选段修改回到原工作并携带版本，不另建“成果聊天”。

## 工作：判断、过程和成果相互解释

轻对话承接快速目标、团队答复与下一次输入。进入沉浸后默认左决策、右过程/结果页签；三个面可自由排列。工作标题与返回位置始终明确，布局与团队配置分开。

- **决策面**：可折叠的当前目标、团队的可读结论、用户交流与确实需要的选择。一般材料缺口不自动变成待决。这里不重复整份成果与所有成员分析。
- **过程面**：按真实问题呈现负责人、材料、公开分析、分歧及修订结果。每个结论可定位来源或成果段落。成员视图/轮次筛选按需打开，不用四个固定步骤填满画面。
- **结果面**：完整成果及当前版本，必要的待核标记；整版/选段交给 AI 整理、比较、导出。版本历史和采用关系按需展开，不常驻完整管理面板。

例如研究员读到摘要、核查员质疑依据、编辑员保留限定措辞，应该形成一条可理解的因果关系。决策面交代处理结论，过程展示原因，结果显示改动后的段落；不能在三个面复写同一条警告。

首次进入时有成果可优先打开结果，没有成果可打开过程；明确“查看过程/结果”的入口尊重点击意图；随后始终恢复用户自己选的页签。运行中只提示新内容，不强制切换。总结过程/复盘仍可直接操作，但属于过程工具，生成内容回到同一结果面。

团队与流程是工作中的次级配置：搭配和流程分别版本化，当前运行快照不变，下一轮生效。初次发送不要求选角色、人数、模型或节点图。停止针对当轮执行，离开、收起或重排只改变视图。

## 资产：把已有积累带回工作

自动保存的工作历史可查找，但资产首页优先呈现用户主动收集的材料、成果与方法。加入资产保存引用与用途，不拷贝第二份成果；“沉淀为方法”才是明确的新产出。

列表主动作是打开了解；详情主动作是“用于工作”。先选择已有工作或新工作，把准确版本和范围加入草稿，发送才调用团队。方法的适用条件与验证状态是内容，不作为每行一排状态徽章。仅收藏不表示已验证、已启用或获准执行工具。

## 定时任务：一次工作变成持续委托

保持左侧直接入口，列表表达做什么、触发和最近实际结果，主动作是查看委托。新建与“将这项工作设为定时任务”使用同一表单；从工作进入时继承目标、资料、团队与结果归属，用户重点决定触发及必要限制。

每个委托绑定一项工作，每次运行和成果版本归回它。运行记录是委托详情的一部分，查看结果打开准确版本。暂停后续触发与停止当次分开；没有新信息显示检查结果，不凑一份报告。需要本地资料但执行位置不可达时说明缺口，不假装远端能读。

## 设置：配置使用条件

服务/模型、能力/权限、数据/设备、通知/外观共用设置壳和分组表单。只有当前动作受影响时，就地提示缺项并提供定向设置入口；从设置返回原草稿，不要求重新输入。设置项没有接入实现时不得展示成功、已同步或全自动保存等承诺。

## 操作统一规则与异常路径

| 情况 | 行为 |
| --- | --- |
| 无内容 | 展示当前领域的真实开始入口；不造示例记录作为用户内容 |
| 未发送展开/退出 | 同一草稿；没有永久空工作或模型调用 |
| 重复发送 | 同一提交身份，防止重复工作和重复付费；界面保留可恢复状态 |
| 运行中补充意见 | 明确提交才进入下一轮待发；停止/失败/待决暂停自动续发，可编辑撤回，不并发覆盖 |
| 模型不可用 | 保留草稿和历史阅读，连接后回原目标 |
| 缺原文 | 就地标明覆盖和对结论的限制；能继续的部分继续 |
| 过时待决 | 告知目标/版本已变，原回答不静默应用到新范围 |
| 生成期间出现新版本 | 保留当前版本和生成候选，准确引用后交给 AI 整理；不提供手工合并，不能覆盖 |
| 窄窗口 | 收起导航，按需切完整工作面；输入不遮正文，拖动有菜单替代 |

视觉规范见 DESIGN；底部对话入口统一见 [COMPOSER.md](COMPOSER.md)，操作图标化，工作身份、引用和必要状态保留文字。当前先用 INTERACTION 的阅读创作、项目接续路径检验页面关系，再扩展静态稿；必须记录对象、动作与返回状态。截图只证明视觉表达，不能证明行为连通。

选中、当前工作、修订与依据限制必须各自表达，不共用一张彩色提示卡。所有页面禁用左侧亮条（包括细左线）标识选中或强调；修订段落保留正文排版，必要时附“已修改”文字，差异在比较版本中查看。普通提示不叠加彩底、圆角和装饰图标。
