## 当前结论：界面再次被否定，停止沿现有结构叠改

进一步根因审查见[产品实现偏差复盘](产品实现偏差复盘.md)：问题不限于 UI。旧工程计划曾将项目理解降为扫描概况；当前项目持续状态、复盘和反馈复用仍有行为及验证缺口。本文件是已有实现证据台账，不足以指导或证明完整产品目标实现；此前“只需重做界面层”的判断收回，保留与重做范围需按产品能力分别判断。

2026-09-13，用户在本轮修改后再次指出界面仍然混乱，并明确提出停止浪费时间和 token。此次界面改造未达到目标；下面记录的改动只是已做工作，不是认可的设计方向或产品完成证据。当前停止功能扩展，撤回最后开始且尚未验证的结构化项目状态报告增量，保留此前数据、底层修复与验证证据。

责任在实现与判断：明知用户反复否定信息主次和工作路径，仍围绕现有面板重新安排功能；把恢复三窗、增加状态、测试通过当作方向成立的依据。此前总结没有改变后续行动。建议重新设计界面层，先验证主要工作路径与可操作界面，不继续在这版布局上扩建；不能据此断言整个底层必须推倒，也不能要求用户重新提供全部已有需求。

上一版仍未满足用户目标。具体误判是把“减少层级”理解成删减同时工作的能力，把过程降为操作记录，把软件项目工作降为弹窗。工程测试验证了按钮和数据链，却没有验证用户是否能看懂判断、比较项目状态、同时对照成员与成果。417 项通过属于上一版功能证据，不代表体验通过。

产品正文 5.2 与 7.1 已按用户明确反馈补齐：过程必须呈现公开分析、依据和修正，并能总结；项目状态必须有对象、范围与依据；项目使用完整多面协作工作区。后续修改不能通过重写产品目标来迁就实现。

当前修正覆盖：

- 保持独立工作台首页，启动不打开最近会话、不自动运行。
- 共用工作区恢复交流、分析过程与成果并行阅读；两面/三面、分别聚焦、恢复和双向分隔条是工作能力。项目选择直接进入同一工作区，浏览不建任务。
- 软件项目入口用紧凑状态表对照目标、阻塞、下一工作和变化依据；项目中可看状态、文件、成果及历史工作。“理解项目”发送后读取已登记的正式资料加入工作，扫描结果不冒充正文。
- 运行时自动保留实际公开答复，补足未主动汇报时的分析内容；过程同源整理成员观点、用户修正与精确成果版本，操作记录退到排障位置。旧记录无法证明的当时想法不补写。
- 界面采用 Taste 中适用于产品的排版、对比度、间距和状态反馈规则；复杂工作流另按[界面与交互验收](界面与交互验收.md) 实际操作。不会套用营销页的大图、装饰或动效要求。
- 保持草稿、位置和请求归属保护，补验项目正文读取、不同项目新工作、并排/聚焦恢复、总结保存和源失败重试。

本轮界面验收未通过，已停止继续扩大修改。工程检查与隔离模型调用只支持各自行为，不推定界面可用或全部能力已完成。

## 工程选择与可靠性

继续使用锁文件固定的 Node.js >=24、Electron、React、TypeScript、Agents SDK、SQLite 和现有 PostgreSQL 信息服务。桌面主进程校验 IPC、处理原生文件选择及系统密钥保存；utility process 管理资料、模型和持久工作；渲染层只能调用明确命令。新领域对象复用同一任务/资料/成果运行时。

同一操作具有请求身份；重复点击和重开重试不会另建相同工作。任务创建与记录写入事务一致。关闭流程等待正在保存的领域操作和账户动作；账户切换丢弃上一账户迟到响应。新建工作返回后立即采用其快照进入工作台，不依赖下一次 React 提交才找到对象。

本机例行由实际 utility process 执行，服务端委托由独立工作服务执行。两者都有固定输入、版本、次数和用量边界；不共享任意本地文件权限。远端模型响应保留真实工具协议，当前 SSE 使用完整上游结果后发送的缓冲模式，界面不声称逐 token 实时流。

AI 与用户服务位于 `services/work-service`，管理员配置上游、账号和权益后即可使用；信息服务沿用独立 API/worker 与 PostgreSQL。官方运营地址、价格、支付及许可证未由产品决定，不创建虚假套餐或模拟扣费。服务部署说明见各自 README。

## 验证依据

工程回归覆盖新机器初始化、文件边界与冲突、任务并发和目标切换、方法版本/范围/实际资源加载、媒体与交付、收藏/备份恢复、例行调度和未知结果、账户切换/清理、跨入口导航及真实 React 表单行为。所有合成项目、数据库、备份恢复和桌面验收都使用临时根目录，不登记到用户真实 AI 体系。

- `npm run typecheck`：根工程、来源契约、信息服务、工作服务。
- `npm test`：本机领域/运行时/界面、来源契约与服务、工作服务；测试替身与真实提供方分开。
- `npm run test:source:integration`：隔离 PostgreSQL，真实 API/worker/桌面推送，19 项通过，运行结束移除测试数据库。
- `npm run smoke`：新机器规则 → 实际 MD → 修订/冲突 → PPTX → 软件 main/dev → 重开，已通过。
- `npm run build`：桌面、信息服务和独立工作服务构建。
- `npm run probe:product -- --keep`：真实 Gemini `gemini-3.8-flash`，主编实际调用研究员与内容编辑、固定方法、读取合成材料、保存脚本、独立交接检查、导出、无变化跳过及关闭重开。本轮已通过；脚本按工具计量为 102 个口播单位、240 单位/分钟估算约 26 秒，清楚标注未试读/未成片。

独立交接检查保留了合成样本中未明确的计价单位、内部标记是否口播和录音交付规格，未把报告生成自动推进为“已交接”或“已验证”。这些结果支持功能行为和该样本的内容范围，不替代真实接收方使用、真实发布或创作者效果验收。

## 实机发现并修复的问题

- 新建收藏或媒体工作立即跳转时，旧渲染闭包还看不到返回的任务。现在同步采用最新快照，回归覆盖“一次提交即进入新工作”。
- 媒体制作/发布阶段缺前一步成果。现在可选准确成果版本，直接读取已保存文件；未知修改拒绝，同一操作重试保留冻结输入。
- 导入收藏原先无法与 Lib 对照。现在遵守已有查找设置，以实际收到的材料匹配最多 3 份相关资产，固定正文/版本；未授权不读取，未比较不声称完成全库比较。
- Gemini 经 OpenAI 兼容服务完成工具调用后，SDK 流式累积器丢失必需签名，续轮返回上游 400，服务表现为 502。完整响应适配器保留提供方字段；真实主编 → 编辑 → 读取 → 保存 → 返回往返已通过。连接测试区分完整响应接续与增量流式。
- 本机代理把公网域名解析为 `198.18/15` 虚拟地址，原安全检查会拒绝。仅本机明确开启的回退在该单一场景使用固定可信 DoH，重新验证所有地址并固定公网连接；私网、混合解析和重定向检查保留。Electron 在信息服务未连接时已实际取得 Example Domain 正文；默认服务端策略保持严格。
- 账户切换与远端取回有迟到写入风险，清理期间还有并发恢复正文风险。账户上下文、成果版本保护和持久清理屏障已补齐，并用并发/中断测试验证；未知消费保留，不自动重试。
- 关闭窗口后的执行已在真实 Electron 测试：16:23:49 UTC 关窗，16:25:14 与 16:26:14 仍记录无变化检查，模型运行次数保持 0；16:26:15 重开恢复。后台功能只有明确启用后生效。
- 媒体续阶段的最终桌面实测已经完成：读取脚本与交接包的准确版本，经过服务模型形成录音说明；依据追加反馈在同一 artifactId 保存为 v2，保留 30 秒上限、WAV 规格和内部标记范围。此前模型把“用户声明自有”外推为确定权利结论，本轮已实际修订并加强运行提示，未把原断言当作验证结果。
- 使用桌面生成的 218,456 字节真实备份恢复到全新临时根：5 项工作、1 个频道、1 件作品、1 份交付和 v2 制作说明关系恢复；例行任务暂停、账户连接未迁移，关闭后重开再次比对通过。
