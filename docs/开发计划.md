本地验证：`npm run typecheck`、79 项 `npm test`、`npm run smoke`、生产构建通过。`smoke` 在一次临时环境内完成新机器规则创建、任务、真实 MD 文件导入、修订冲突、PPTX、项目 main/dev 和重新读取。真实模型探针与确定性 SDK 测试分别记录，测试替身不算模型实测。

桌面验收使用独立的合成读书小组资料：从原生文件选择导入 MD，修改目标后真实团队协作完成；PNG 已查看、PPTX 已落盘，独立成果窗口手动修订保存到新版本。重开后原任务和第 5 版手动修订均可读取；修复相邻组件 key 冲突导致的任务切换混屏，并在桌面反复往返两个任务验证；独立资料窗口、成果窗口以及导入前草稿的目标/学习类型/CTO/Gemini 配置保留已复验。任务材料与成果保留在本机供体验。PPTX 的 ZIP、关系和可编辑文本 XML 已核查，演示软件中的逐页版式体验仍待扩展验收。

SDK 取消不能自动保证任意嵌套工具恢复：当前使用受控 SDK 子调用，分别保存父子真实 RunState、已完成委派回信及工具账本，在受管工具边界自动批准已授权操作，无额外用户审批弹窗；测试已验证嵌套恢复不重复写入。会话使用本地消息与按目标构造的有限上下文，尚未实现计划中的独立 SQLite-backed SDK Session 类。工作引擎异常退出时明确报错，重新打开应用后接续；自动进程重启留待下一增量。

当前导出限制：PNG 是当前 MD/HTML 的静态排版截图；PPTX 由文字内容分页为可编辑文本，不把任意 HTML 布局无损转为幻灯片。show-me 未安装为运行时插件，其参考呈现思路不等于具备全部导出能力。PDF 不含 OCR 与复杂图表理解。`npm audit` 当前报告 PPTX 依赖链 `image-size` 的两项高危告警，已核查最新版本暂无修复；当前仅输出文本幻灯片，不调用该图片尺寸解析路径，增加 PPT 图片嵌入前需解决依赖问题。

本轮交互验收：原有三项任务完整保留；三窗任务联动、成果折叠后保留草稿、原生缩放与布局恢复已在 Electron 核对。合成成果手动修订到 v6，收藏后修改到 Lib v2，再复用到另一项任务；重开后继续可读取。一次真实 Gemini 统筹→研究员核查→公开进展摘要→原成果保存到 v7 已通过，成果 ID 保持、没有增加同名文档，落盘 hash 匹配。

可视化只消费公开执行事件、资料引用和显式进展摘要，不展示模型原始隐藏推理。SDK 私有检查点保留提供商继续运行所需的原生状态；它不属于前台过程视图。新版运行协议使旧 SDK 检查点失效后从已保存材料继续，历史和已提交成果保留。

下一增量：优先接通一条平台采集，扩展“资料→研究→可复用资产”的闭环，补充 Google 专项 Deep Research、项目反馈与更完整的产物质量验收；同时减少无必要的重复成员调用与同主题重复成果。四块首版范围不缩减，当前不宣布完整首版发布。


用户交互纠正（本轮）：三块工作区域必须位于同一个产品窗口内。移除独立原生辅助窗的实现，旧布局只迁移任务选择；初次进入新版时采用完整应用容器与默认三面板。分隔线拖动在本地即时反馈、释放后保存比例；折叠/放大只调整产品内面板，保留编辑与加工草稿。此前的独立原生窗口记录仅描述上一轮验收，不再是当前产品交互。 本轮 Electron 实测同一界面中的三块区域同时可见；竖线 52%→46%、横线 50%→40% 的实际拖动及落盘通过，释放后首次编辑点击可用，重开后比例与任务正确恢复；折叠/展开/放大/还原保持未保存草稿。

## 1. 首版目标与第一交付

首版同时交付四部分：真实 AI 与多 Agent 底座、AI 工作台、Codex 可接手的项目初始化、通过团队交互完成的文档与成果处理。信息吸收、Lib 积累、研究与创意工作共用这套能力，不拆成独立应用。

**第一交付：导入真实资料 → 团队研究与核查 → 写入 MD → 按 Y 的意见修改 → 退出并重开后继续。** 这是最先贯通的工作，不代表首版范围到此结束。项目初始化、信息源、常规文档输入、信息图与 PPT 随后补齐；信息源适配可在公共接口稳定后并行推进。

首版只在应用前台运行期间执行。可以等待有进展的长任务；不设置产品级总时长或费用额度，提供停止、恢复及可配置限制的入口。网络请求超时、重试上限、并发控制与停滞检测仍需实现。

## 2. 工程选型

| 部分 | 首版决策 | 选择的边界 |
| --- | --- | --- |
| 桌面与界面 | Electron + React + TypeScript，先交付 macOS 自用版本 | 单个原生窗口内左主右上下三面板，共享同一任务；可拖动分隔线、折叠、放大/还原并保存布局；后续再扩平台 |
| Agent 运行时 | OpenAI Agents SDK TypeScript，复用模型循环、工具、委派、转交、流式事件和会话接口 | 产品自己管理任务与协作语义，不从零重造通用 Agent 框架，也不依赖实验性托管多 Agent 能力 |
| 本地状态 | SQLite 保存元数据、事件、会话、目标版本、委派与执行记录 | 项目 MD 原文仍在项目路径，数据库不另存一份竞争的权威正文 |
| 模型配置 | 支持多个连接配置，成员默认配置 + 任务覆盖 | 首批适配 Gemini 原生、DeepSeek OpenAI 兼容、本机 Ark 配置；具体可用模型和能力逐项实测 |
| 专项研究 | Google Deep Research 作为独立工具适配器 | 由研究员委托并核查结果，不把远端服务当作团队身份或本地常驻进程 |
| 产物 | MD 为主要正文，信息图和 PPT 有独立生成、预览与导出流程 | show-me 复用呈现方法；HTML slides、PNG、PPTX 分别验收，不互相冒充 |

SDK 支持 agents-as-tools 和 handoff 两种协作模式，以及代码侧并行编排；采用它们构建产品的协作流程。[官方协作指南](https://openai.github.io/openai-agents-js/guides/multi-agent/)

模型适配先采用官方已有入口：Gemini 普通模型通过 `@openai/agents-extensions/ai-sdk` 的 `aisdk` 与 `@ai-sdk/google` 接入；DeepSeek、Ark 分别创建 `OpenAIChatCompletionsModel` 实例，明确协议、端点与模型，避免修改进程全局客户端。选择顺序为任务覆盖、成员配置、默认配置。AI SDK 适配器当前仍标 beta，锁定兼容版本后验证工具与流式；Google Deep Research 保持独立。[官方适配器](https://openai.github.io/openai-agents-js/extensions/ai-sdk/)

配置层显式映射现有 Gemini 环境变量，不能依赖 Google provider 默认识别 `GEMINI_API_KEY` 或 `GOOGLE_API_KEY`；其默认变量名为 `GOOGLE_GENERATIVE_AI_API_KEY`。Ark 的 OpenAI 与 Anthropic 端点也不能混用，分别按协议读取配置。[Google provider](https://ai-sdk.dev/providers/ai-sdk-providers/google-generative-ai)

## 3. 模块边界

以下为模块职责；当前在一个 TypeScript 工程内按职责分目录。desktop/workbench/shared 与 core 内的 runtime/models/store/files/sources/system/service 已建立，平台采集与 Lib 的完整能力继续扩展。

| 模块 | 负责内容 | 交付给其他模块 |
| --- | --- | --- |
| `desktop` | 窗口、应用生命周期、文件选择、凭据访问、受限 IPC | 经过校验的命令入口与窗口状态 |
| `workbench` | 目标讨论、成员直聊、进展摘要、资料/证据与成果/版本窗口 | 用户意图、局部修改、停止/继续操作；不直接执行文件或模型调用 |
| `runtime` | SDK 适配、成员运行、工具注册、子任务调度、协商与结果交接 | 标准化运行事件、工具结果、委派回信与产物提案 |
| `state` | SQLite、目标版本、会话与任务事件、执行账本、恢复检查 | 可追溯的当前状态与恢复所需材料 |
| `models` | 多连接配置、每次运行的模型选择、能力探测、用量记录 | SDK 可用的模型实例；不支持的能力与错误明确返回 |
| `sources` | 文件、URL、GitHub、知乎、抖音与 X 的独立采集适配器 | 来源 ID、实际内容、观察时间、分页进度、覆盖范围与缺失项 |
| `artifacts` | 输入解析、MD 修订、版本比较、信息图/PPT 生成与导出 | 文件位置、内容摘要、版本、来源关联与实际导出结果 |
| `projects-lib` | 本机 AI 规则体系的发现、引导创建与校验，项目初始化与反馈，资料检索、知识/能力资产关联 | 本机规则就绪状态、项目环境核查结果、可复用资产及其验证与采纳状态 |

Electron 主进程保持轻量，Agent 运行与重解析放入可重启的 utility process；其退出与重启由主进程管理。长任务不能阻塞输入和停止操作。[进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)

界面启用 context isolation 与 sandbox，关闭 Node integration；IPC 校验发送者、参数与路径范围。外部页面、导入 HTML 与生成可视化在没有本机能力的隔离视图中呈现；不把任意页面接入应用 IPC。[Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)

## 4. AI 与协作底座先立住的规则

1. **任务归属**：项目、任务、成员运行、工具执行与产物都有稳定 ID。共享的是有效目标、必要资料、已确认判断与成果引用，不是所有项目和完整聊天的混合上下文。
2. **真实协作**：稳定成员可委派专项工作、向其他成员追问、接收修正并引用对方成果。委派信箱记录发起者、接收者、目标版本、问题、依赖、结果与处理状态；SDK 调用与信箱记录对应。是否参与由实际任务决定，不固定三人轮流发言。
3. **目标修正**：Y 的否定或修改产生新目标版本；系统确定受影响的任务，停止或使其失效，并重新调度。旧版本的迟到结果可留作历史，不能自动进入当前结论或覆盖当前成果。
4. **状态可信**：分别记录运行中、等待工具/成员/用户、暂停、失败、完成与待核实。界面总结基于已收到的事件，不生成百分比假进度；完成必须有可读取的成果和执行证据。SDK 的流式事件是输入，不直接等同于产品完成状态。[流式事件](https://openai.github.io/openai-agents-js/guides/streaming/)
5. **会话与恢复**：实现 SQLite-backed `Session`，同时保存产品自己的事件与检查点。SDK 会话历史用于后续模型轮次，不代表断电后可自动恢复任意正在执行的工具；可序列化的运行状态按 SDK 实际支持处理，其余从已完成边界继续。[Sessions](https://openai.github.io/openai-agents-js/guides/sessions/)
6. **工具副作用**：调用前记录操作 ID、目标路径、输入版本和授权范围，调用后保存真实结果。写文件采用暂存、原子替换与版本检查；数据库和文件之间保留提交标记供重启核对。未知结果先检查现场，不自动重放可能已执行的初始化、写入或外部操作。
7. **授权与停止**：任务内常规判断和已授权操作持续推进，不反复让 Y 审批同一范围。新增外部动作或超出授权时再请求明确决定。停止传递到运行、子任务和可取消工具；不能取消的远端操作如实显示，并保存服务 ID 以便查询。
8. **本地可控**：凭据保存在本机凭据存储，配置只保存引用；日志与默认追踪留在本机，显式关闭 SDK 默认远端 trace 导出。资料外发策略与预算限制预留统一入口，后续细化；这不免除当前的资料和工具授权范围。

## 5. 五个可验收增量

### 增量一：真实资料到可修改的成果

- 建立 Electron 工程、应用内三个面板的最小组织、SQLite、配置页、一个通过探测的真实模型连接和本地文件工具。
- 导入 MD/TXT/JSON，创建研究任务；统筹能调用研究员检查材料，接收结果并写出带来源位置的 MD。需要外部搜索的任务使用实际可用搜索能力，缺少时明确限制。
- Y 提出修改后，能查看修订并保存；正常退出、重开后保留目标、材料、版本与继续入口。
- **验收**：用一份真实材料完成全流程，查得到两次独立 Agent 运行、工具调用及落盘文件；仅返回聊天文字或模拟事件不算通过。

### 增量二：协作、修正与异常恢复

- 补齐成员直聊、委派信箱、协商追问、并行子任务、目标版本、运行检查点、停止与失败处理；主面板保留简短决策摘要，详情和产物进入应用内辅助面板。
- 验证 Gemini 原生、DeepSeek 兼容和 Ark 配置通路；按成员选择与任务覆盖，记录每次运行实际使用的配置。接入 Google Deep Research 的提交、状态查询、结果导入与可用的取消能力。
- **验收**：运行中改变目标、切换成员、断网、终止工作进程和重开应用后，均能辨认有效工作与未决结果；旧目标产物不能覆盖新成果，成功的工具不重复执行。

### 增量三：从讨论到 Codex 可接手的项目

- 团队整理产品雏形、需求、约束、待解决问题与已有证据，形成初始化方案；工程设计与实际代码开发仍由 Codex 接手。
- **先让本机规则体系就绪**：当前机器从 `/Users/Admin/AI/system/system.json` 发现并读取现有 Policy、系列、文档归属、项目登记及接口。新机器默认使用当前用户的 `~/AI`，也支持显式根目录配置。AI 根目录或整套体系缺失时，实际创建体系并通过校验，再初始化项目；不止提供操作指引。已有有效规则优先使用，不以产品模板覆盖。
- 通过 Policy 适配器建立稳定项目 ID、系列、目录、manifest、规则区块、README、产品正文、研究/反馈入口及适用的 main/dev worktree。路径来自本机配置，不写死当前用户目录。
- 创建远端、推送等外部动作按已有授权执行；未授权或缺少权限时交付完整本地环境，远端状态单独记录。规则体系初始化只处理自身受管目录和必要入口，不顺带整理用户 Home。
- **验收**：完整已有、全新、残缺体系和自定义根路径分别测试；各自覆盖中途失败与继续、同名冲突、重复运行、未知文件保留。完整项目通过 validate、observe、manifest/规则、Git status、worktree 和文档入口检查，Codex 能直接读到交接材料。只在开发机已有 AI 目录的前提下成功，不算此功能完成。

本机规则初始化包必须具备以下内容与行为：

| 内容 | 实施约束 |
| --- | --- |
| 根目录和单一规则源 | 创建 AI 的 `system/`、`knowledge/`、`resources/`，按配置准备 Code 根；生成 `system/POLICY.md`、`system/system.json`、说明入口和 AI/Code 的 AGENTS 规则链接。已有同名文件或链接先辨认归属，保留未知内容 |
| 完整可解析的配置 | 提供 `work.json`、`series.json`、`projects/`、`knowledge.json`、`resources.json`、引用到的 schema、项目模板，以及知识/资源的 catalog 入口；所有引用均指向当前机器的有效位置 |
| 校验、观察和投影 | 初始化包提供可运行的 validate、observe、project_rules 接口或与其契约一致的实现；只读观察与有授权的初始化写入分离，配置不得携带任意待执行命令 |
| 模板来源与可移植性 | 随产品提供版本化、经过审阅的通用规则模板；新环境的路径、观察范围和规则链接统一生成，不硬拷本机脚本中的绝对路径或 GitHub 用户名；不复制已有项目、账号、私人资源清单和凭据 |
| 已有与残缺环境 | 检查 schema 版本、引用和文件归属；自动补齐可确认且不冲突的缺项。损坏或不兼容的配置保留现场，给出具体修复路径，不当作空目录覆盖；应用升级也不覆盖用户规则 |
| 失败与重复操作 | 记录创建步骤与模板版本；失败后能核查并继续。重复运行不重复登记、不建立竞争的权威正文，也不覆盖用户后来修改的规则 |

### 增量四：信息吸收与 Lib 复用

- 公共采集接口在增量一建立后即允许并行适配：本地文件/链接、GitHub 官方来源、知乎官方 CLI、抖音、Grok Build 的 X 能力；AIGCLINK 用作发现线索，结论回到原始来源。
- 抖音由程序批量处理 JSON 和分页：已观察到收藏页真实 POST 返回 HTTP 200、`status_code: 0`、`aweme_list`、`cursor` 和 `has_more`，两份成功响应的游标不同，请求体有 `count: 10`；尚未完成程序采集、修改游标后的签名重放或全量导入。优先验证 Chrome 扩展桥接复用用户正常登录的会话；扩展的响应体获取需独立能力与相应授权，普通 `webRequest` 不够。独立持久浏览器会话作为后备。程序选择有效的会话内分页请求或监听网站正常加载的 JSON；DOM 仅备用，不让模型逐条翻页。[当前验证记录](参考/抖音收藏接入验证.md)
- 基础 Radar 在前台刷新指定与预置来源，去重、合并主题、说明相关性并保留新证据；可从知识点发起扩展任务。Lib 关联来源、项目、主题、产物和反馈，支持后续检索与复用。
- **验收**：至少一个真实外部来源完成“取得内容 → 消化 → 关联已有资料 → 进入研究成果”；分页重启不重复入库，缺失不当作删除，标题/描述不冒充全文或完整视频理解。其余来源按实际覆盖单独记录，不阻塞核心闭环。

### 增量五：常规文档与可交付成果

- 增加 PDF、DOC/DOCX 解析，区分文字提取、版面/图表理解与 OCR；保留原文件和位置，解析失败或缺页显式提示，不要求原格式无损编辑。
- 团队能围绕同一 MD 做局部修订与审视；引入 show-me 的 Mermaid、信息图和 HTML 幻灯片方法，并补齐 PNG 与原生 PPTX 的独立导出能力。
- **验收**：各输入格式用真实样本核对关键内容，扫描件和复杂版面分别说明覆盖；PNG 可打开且文字清晰，PPTX 能由演示软件打开且关键文本/对象可编辑，HTML 预览不算 PPTX 导出。成果可在辅助面板查看、再次修订，并保留来源与版本。
- 四块首版能力串联完成一次项目孵化与一次研究任务；已有工作重开后接续，至少复用一项此前采纳的资产，才进入首版体验验收。

## 6. 配置与缺失项怎样处理

| 缺失或不确定项 | 开发处理 | 真实交付条件 |
| --- | --- | --- |
| 模型 endpoint、model ID、凭据或服务权限 | 先完成配置结构、适配器和错误状态；按现有获授权配置选择一条真实连接开展主线 | 每个配置分别测文本、流式、工具、多轮工具结果、取消和错误处理；不能仅凭“连接成功”标为可协作 |
| Gemini 原生与 SDK 的映射 | 经 `Model`/`ModelProvider` 或经核查的官方适配扩展接入；保留提供商特有能力 | 先测工具结构、消息往返及流式事件，再定适配细节；不能假设兼容模型支持全部 SDK 能力 [模型接口](https://openai.github.io/openai-agents-js/guides/models/) |
| 本机 Ark 配置具体形态 | 由独立适配器读取获准的配置引用，核查接口类型及模型，不把“本机配置”解释成本地推理 | 实际请求成功并通过所需能力探测；不输出或复制密钥到仓库 |
| Google Deep Research 权限或服务不可用 | 保留独立能力入口和清楚状态，研究员仍可利用现有资料与已接通搜索完成研究 | 专项服务单独实测；普通模型研究不标为 Google Deep Research |
| 平台账号、CLI、分页或全文尚未验证 | 接口与采集器可先开发，允许手动文件/链接导入；平台适配并行推进 | 来源状态分未配置、待验证、部分可用、已验证；收藏列表、正文、视频转录分别计证据覆盖 |
| 全部模型连接暂缺 | 完成界面、持久化、工具及自动化验证，开发夹具明确标记且不进入用户真实任务 | 至少一个获授权的真实模型完成增量一之前，不宣称 AI 底座已交付 |

当前 Gemini 已实测可用；DeepSeek 尚缺可验证的账号配置，Ark 的当前 Coding Plan 账号权限不可用。各连接独立显示状态，不因为环境变量存在或另一渠道成功而标为 ready。

测试只为关键风险设验证：状态转换、版本冲突、恢复与工具幂等用确定性测试；模型与来源用小规模真实集成验证；窗口交互和产物打开做端到端检查。测试替身证明工程行为，真实调用证明能力，两类结果分开记录。

下一次开发从本轮状态继续，补平台来源、深化资产复用、专项研究和项目反馈，不重做当前底座，不再回到技术栈讨论。
