### C/D 的工程决定与当前范围

- **独立服务有内容**：本机运行 PostgreSQL、API 与 worker，桌面关闭不停止采集计划。默认供给为 Hugging Face Blog、GitHub Changelog、少数派、Solidot、OpenAI Agents JS 更新，分 AI 与模型、开发工具、数字生活与方法、科技与新知四类。用户另加公开网址或 RSS/Atom；来源提供的新文章各自成为条目，稳定外部 ID 去重，旧文章修订保留版本。
- **先比较职责，再选组件**：研究中的 FreshRSS/Miniflux 可提供完整订阅阅读系统，RSSHub 主要补充来源路由，Gorse 需要反馈与推荐评估样本。本轮有限公开 feed 不需要另起完整阅读产品；选择原生 RSS/Atom 解析、已有安全网络层与 Readability 正文提取，复用经过核对的队列/版本/交付底座。上述产品未安装也未声称实测；复杂来源出现后按缺口引入，不将当前解析器等同完整平台能力。
- **覆盖诚实**：每次 feed 观察取按发布时间排序的最近最多 40 条；没有发布时间则保留提供顺序。最多为前 12 条缺全文条目补取公开网页，失败保留摘要及缺失说明。feed 自带正文与仅摘要区分；取得正文不意味着读过页面中的媒体。发布时间与接收时间分别保存；兼容早期缓存中已明确写入正文的 feed 发布时间，不重写历史成果。HTML 正文保留段落，进入文章从标题开始，返回恢复列表位置。feed 暂时缺项或空列表不删除历史。RSS/Atom 条目列表不宣称完整历史回填。
- **服务器整理后交付**：服务器独立调用 Gemini，为每个租户/分类的最近最多 12 条材料形成重点与主题，合并相关信息、保留分歧和限制。每条材料最多提供 7,000 字符，整理保留实际输入片段、来源 URL、item/revision ID 和模型标识；引用必须来自输入集合。材料/模型不变复用结果，失败保留上次可读结果并退避重试。该阶段是有限分类编辑，不是已经验证的个性化推荐系统。
- **本地背景留本地**：服务器只取得关注来源的材料，不挂载用户项目、Lib 或桌面数据库；模型请求 `store:false`，不发送租户内部 ID，只保存可公开阅读的最终结构化正文。真实 Gemini 使用官方 [Interactions 结构化输出](https://ai.google.dev/gemini-api/docs/structured-output)，不展示或保存模型内部思考。模型密钥来自服务运行环境，设备令牌经系统 safeStorage 加密，均不进入快照或日志。
- **客户端直接阅读**：默认“信息阅读”提供总览、订阅服务、我的来源、分类/来源筛选及本地关键词搜索。“先看重点”展示服务端已生成结果，可展开观点、核查原始材料片段，再进入文章或原站。正常接收和阅读不触发本机团队任务；有需要时从文章交给团队，继续使用已有决策/过程/成果与 Lib。历史团队处理入口仅在有记录时显示。
- **接续与版本**：应用内输入服务地址即可配对，当前本机默认地址 `http://127.0.0.1:47321`；保存后重开自动连接。正文和游标仍原子写入本机 SQLite，主题另存按服务实例/租户隔离的离线镜像。正在读的文章保持选中版本，新修订到达后提示切换，不在阅读中替换正文；主题核查保留整理时的材料片段。

### A 的具体工程决定

- 不新增知识库产品、向量服务或新目录体系。只检索当前 AI 根中由用户明确收藏的 Lib 文本资产，不扫描其他任务、项目正文或私人目录。初期采用本机中英文分词与关键词候选排序，最多自动选入三项；没有匹配就不凑数。设置可关闭自动选入，显式选择仍可用。该检索不是语义相似度或相关性质量已验证。
- 每次开始/继续工作前准备上下文。来源带资产 ID、版本、内容 hash、反馈修订和候选原因；模型按需读取正文与反馈。替换后的快照留作历史，不再进入当前运行；原成果和历史反馈保留。关键词命中、已选入、模型实际读取、用户反馈有效是不同证据层。
- SQLite 新增按 AI 根与资产隔离的追加式反馈账本。判断修正、使用有效、未达预期分别记录；使用结果需实际用途、条件与观察依据。可关联已选入该资产版本的任务及成果，保存关联时的身份和版本；删除会话不删除资产反馈。模型没有写“用户反馈”或自动认证能力的工具。
- 状态保守投影为“尚未验证 / 有反馈待处理 / 用户反馈有效”。有效反馈只支持被观察的正文 hash，不继承到新版本，也不等同工具实测。未解决的修正或失败优先提示；用户真正修订正文并明确勾选处理的反馈后才记解决，单纯换标题或保存同一正文不消除问题。
- 反馈请求带稳定 ID、资产版本/hash及反馈修订，重复请求幂等，旧请求、过期成果版本或不同资产的归因拒绝。反馈和正文修订使相关工作暂停并提升目标版本，迟到写入不能覆盖；下次运行重新准备当前上下文，不直接后台追加模型调用。重开会核对“反馈已落库、任务尚未标记”的中断边界；此前手动复用的 Lib 快照仅在路径、版本和内容 hash 对得上时补全关联。接续引用原始用户请求，不伪造另一条用户消息，也不把无关旧目标重新送入模型。
- 沿用决策/过程/成果和 Lib 页面。资料中可看到为什么带入、版本与反馈，并回到对应资产；Lib 可直接记录反馈、在原正文修订中处理反馈、交给同一团队继续产出。反馈和保存过程保护输入，切换后保留草稿和提交状态。

当前限制：自动查找为最多三项文字资产的本地关键词候选，不是语义搜索。团队按需读取与应用判断；应用不会以已选入或已阅读自动认证知识。已生成的修订说明书与 Lib 正文仍各自保留来源，团队提出修订后直接采纳回原 Lib、批量材料到主题资产的演进和真人实际使用验收留在 B/E。没有读取到的媒体、未处理的反馈或失败证据仍保留相应状态。

### 后续持续约束

独立服务的价值包括类别供给、筛选整理、个人订阅结果与反馈，继续避免将服务器退化成原文中转。完整 Lib、项目和私有收藏不默认上传；个人来源能力不以购买官方服务为前提。首版项目初始化、文档输入输出、真实协作和恢复义务继续保留。

本轮只运行本机服务，不发布远端服务、不创建收费资源、不公开仓库。下方旧记录中的自动本机消化与“safeStorage 配对待完成”等表述是历史状态，均以本节 C/D 的当前实现为准。

| 产物 | MD 为主要正文，信息图和 PPT 有独立生成、预览与导出流程 | show-me 复用呈现方法；HTML slides、PNG、PPTX 分别验收，不互相冒充 |

SDK 支持 agents-as-tools 和 handoff 两种协作模式，以及代码侧并行编排；采用它们构建产品的协作流程。[官方协作指南](https://openai.github.io/openai-agents-js/guides/multi-agent/)

模型适配先采用官方已有入口：Gemini 普通模型通过 `@openai/agents-extensions/ai-sdk` 的 `aisdk` 与 `@ai-sdk/google` 接入；DeepSeek、Ark 分别创建 `OpenAIChatCompletionsModel` 实例，明确协议、端点与模型，避免修改进程全局客户端。选择顺序为任务覆盖、成员配置、默认配置。AI SDK 适配器当前仍标 beta，锁定兼容版本后验证工具与流式；Google Deep Research 保持独立。[官方适配器](https://openai.github.io/openai-agents-js/extensions/ai-sdk/)

配置层显式映射现有 Gemini 环境变量，不能依赖 Google provider 默认识别 `GEMINI_API_KEY` 或 `GOOGLE_API_KEY`；其默认变量名为 `GOOGLE_GENERATIVE_AI_API_KEY`。Ark 的 OpenAI 与 Anthropic 端点也不能混用，分别按协议读取配置。[Google provider](https://ai-sdk.dev/providers/ai-sdk-providers/google-generative-ai)

仓库先采用渐进拆分：保留现有桌面目录与构建入口，新建独立包 `services/source-service` 和 `packages/source-contract`，避免为服务化先搬动全部已完成代码；确需登录态后再增加独立的 `clients/source-edge`，不把它塞入 workbench。各包有适用的独立依赖、构建和测试，`source-service` 另有迁移与启动命令，根级检查统一调用。服务端能在没有 Electron、用户 AI 目录和桌面 SQLite 的独立主机上启动并通过网络服务桌面，才算真正完成剥离。

## 3. 模块边界

以下为目标模块职责。当前 `desktop/workbench/shared` 与 `core` 内的 `runtime/models/store/files/sources/system/service` 已建立；现有 `sources` 同时混有本地材料与外部 URL 取得逻辑，4A–4B 按下表拆分。可以先留在同一仓库，但必须形成桌面与服务两个独立运行/发布单元；启用 edge 时它是第三个独立单元。桌面不能通过源码导入绕过服务契约。

| 运行位置 / 模块 | 负责内容 | 交付给其他模块 |
| --- | --- | --- |
| 本机 `desktop` | 窗口、应用生命周期、文件选择、本机凭据访问、受限 IPC | 经过校验的命令入口与窗口状态 |
| 本机 `workbench` | 目标讨论、成员直聊、Radar 阅读、进展摘要、资料/证据与成果/版本窗口 | 用户意图、局部修改、来源关注/取消关注、停止/继续操作；不直接调用平台 |
| 本机 `runtime` | SDK 适配、成员运行、工具注册、子任务调度、协商与结果交接 | 标准化运行事件、工具结果、委派回信与产物提案 |
| 本机 `state` | SQLite、目标版本、会话与任务事件、执行账本、来源条目缓存与恢复检查 | 可追溯的当前状态与离线继续所需材料；不竞争服务端采集状态的权威性 |
| 本机 `models` | 多连接配置、每次运行的模型选择、能力探测、用量记录 | SDK 可用的模型实例；不支持的能力与错误明确返回 |
| 本机 `materials` | 本地文件、粘贴正文，以及用户选入任务的远端条目快照 | 任务可读材料、来源引用、内容 hash 与覆盖说明；不含平台连接器、分页和调度 |
| 本机 `source-client` | 服务地址与能力探测、设备认证、关注配置、显式同步、增量游标、缓存和错误/过期状态 | 只经 `source-contract` 取得条目和提交用户明确的来源操作；服务不可达时不伪造刷新成功 |
| 可选本机 `source-edge` | 在用户明确触发或授权的范围内，代服务取得只能由本机浏览器会话访问的原生响应；剥离 Cookie、header 与未获准字段后封装 edge ingest | 向服务提交平台原生的最小载荷和外部 ID；不保存来源配置、分页权威状态，不生成 canonical item，不负责语义规范化或访问本地 Lib |
| 本机 `artifacts` | 输入解析、MD 修订、版本比较、信息图/PPT 生成与导出 | 文件位置、内容摘要、版本、来源关联与实际导出结果 |
| 本机 `projects-lib` | 本机 AI 规则体系的发现、引导创建与校验，项目初始化与反馈，资料检索、知识/能力资产关联 | 本机规则就绪状态、项目环境核查结果、可复用资产及其验证与采纳状态 |
| 共享 `source-contract` | `/v1` 请求/响应 schema、稳定 ID、错误码、能力协商、同步游标和兼容性测试夹具 | 由契约生成或校验的服务端路由与桌面客户端类型；不共享数据库实体或内部实现 |
| 服务端 `source-api` | 认证、租户范围、来源目录、连接、关注、同步、导出/删除和权益查询入口 | 经授权的版本化资源；不暴露第三方凭据、内部队列或跨租户数据 |
| 服务端 `source-connectors` | RSS/公开 URL/GitHub/知乎/抖音/X 等发现、授权、取得、校验、解析与 canonical 规范化；也校验 edge ingest | 带外部 ID、原始位置、内容层级、时间、hash、覆盖范围和缺失项的候选条目 |
| 服务端 `source-jobs` | 显式同步与定时计划、持久作业、租约、超时、重试退避、来源级限流、分页接续和停滞回收 | 可审计的运行、检查点和失败状态；重复执行不会重复交付条目 |
| 服务端 `source-store` | PostgreSQL 迁移、来源/条目版本、连接引用、游标、交付、权益和用量事件 | 服务端权威采集状态、可导出数据与审计记录；大对象仅保存受政策允许的引用或对象存储键 |

Electron 主进程保持轻量，Agent 运行与重解析放入可重启的 utility process；其退出与重启由主进程管理。长任务不能阻塞输入和停止操作。[进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)

界面启用 context isolation 与 sandbox，关闭 Node integration；IPC 校验发送者、参数与路径范围。外部页面、导入 HTML 与生成可视化在没有本机能力的隔离视图中呈现；不把任意页面接入应用 IPC。[Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)

## 4. 信息源服务边界与订阅准备

### 4.1 数据权威与运行边界

信息源“整体剥离”指所有可重复观察的外部来源，以及用户显式交给来源系统取得的 URL，统一由 `source-service` 管理，不再把平台实现加进 Electron 或本地 Agent utility process。一次性本地资料导入不是信息源关注：文件和粘贴正文继续本机处理。已有任务中的 URL 内容和来源 ID 保留，迁移时只补 provenance 映射，不重写成果或 Lib。

任务中的临时 Web 检索和 Google Deep Research 是 Agent 为当前问题调用的研究能力，不是持续信息源；它们可以继续由本机 runtime 直接使用获准的模型/研究适配器，引用和报告作为本机任务材料保存，不创建来源关注、服务端分页或调度。用户若要持续观察其中某个网址或账号，必须再经 `SourceGateway` 登记到服务。两条路径在事件、界面和数据类型上明确区分。

| 数据 / 状态 | 权威位置 | 边界 |
| --- | --- | --- |
| 原始文章、视频、收藏与账号状态 | 外部平台 | ytriple 只保存带时间、内容层级和覆盖范围的观察结果，不声称替代原平台 |
| 来源目录、连接器能力、抓取运行、分页检查点、条目与不可变修订 | `source-service` | 服务端是 ytriple 采集状态的权威；桌面只有离线镜像，不能自行推进服务游标 |
| 用户的来源连接、关注范围与条目交付状态 | `source-service`，按租户隔离 | 便于自部署、跨设备和以后托管；暂停关注、删除服务数据与删除本地资产是不同动作 |
| 平台凭据 | `source-service` 配置的 secret store（自部署或托管），或本机 `source-edge` 的系统凭据存储 | 数据库只存凭据引用；浏览器 Cookie 默认不上传，服务端和日志均不可返回密钥 |
| 任务、会话、项目上下文、团队判断、成果、反馈与 Lib | 本机工作台 | 服务端不得挂载或扫描用户项目和完整 Lib；以后托管个性化处理也必须单独选择并最小化上传 |
| 服务权益、额度与用量事件 | `source-service` | 只表达服务可用能力和可核对消耗，不决定本地数据所有权 |

数据模型按实际阶段增加，避免为了未来收费一次建成完整 SaaS：

| 阶段 | 实体与约束 | 完成时机 |
| --- | --- | --- |
| 最小跨网络切片 | `tenant`、`principal`、`device`、`connector`、`source`、`fetch_run`、`source_checkpoint`、`source_item`、`item_revision`、`delivery_change` | 公开 URL 从独立服务器取得并同步桌面之前 |
| 持续/登录来源 | `connection`、`source_follow`、凭据引用与授权状态 | 第一条持续平台来源之前 |
| 托管准备 | `service_entitlement` 策略接口、幂等 `usage_event` | 托管前加固；首期可有默认策略，不做支付状态机 |
| 有证据再增加 | 大正文/媒体的 `content_blob`、跨来源 `dedup_cluster` | 样本证明 PostgreSQL 内联内容或单源身份不足之后 |

所有租户私有表必须带 `tenant_id`，远端引用包含 `server_instance_id`，登录来源的正文不得跨租户复用。正文覆盖至少区分 `listing`、`metadata`、`fulltext`、`transcript` 和 `vision`，请求失败或某次列表缺项不能自动生成删除记录。

公共来源在许可和保存政策允许时可以复用一次基础采集与内容指纹，但每个租户的关注、交付、过滤和理解独立；没有再分发权时只共享抓取状态、规范化元数据或 hash，不把整篇正文做成公共内容库。私有收藏、账号后台和 edge 上送内容始终按连接租户隔离。

这里固定两个不同术语：`source_follow` 表示用户关注一个内容来源，`service_entitlement` 表示未来产品订阅赋予的能力与额度。代码、接口和界面不得用同一个 `subscription` 对象混合两者。

### 4.2 契约、同步与恢复

- 契约按纵向切片演进，并在每一层先提交可审阅的 OpenAPI/JSON Schema 与兼容夹具。公开 URL canary 冻结 `/v1/capabilities`、首次 pairing/bootstrap、URL source upsert + refresh 提交、任务查询、按游标读取 changes、按 item/revision 取得内容所需的最小资源；配对可由一次性 CLI 或部署端代码完成。持续平台来源再加入连接/重新授权、关注和取消；若需要 edge，再增加 job claim/poll、edge ingest、ack/replay；托管加固再加入 entitlement/usage。未进入当前切片的资源不能用空实现冒充已交付。
- 服务生成稳定 ID。所有写请求带 idempotency key，配置修改带版本号或 ETag；所有响应给出协议版本和服务实例，item/revision/change 的内容载荷另给观察时间、内容 hash、覆盖层级和缺失项。桌面只依赖 `source-contract`，不能读取服务数据库或导入连接器代码。
- 同步采用“初始分页快照 + 单调变更游标 + 至少一次投递”。桌面在同一 SQLite 事务中幂等写入 `(server_instance_id, tenant_id, item_id, revision_id)` 并推进本地游标；Agent 消化和 Lib 提升是之后的独立可恢复阶段，不阻塞收件同步。
- 变更流区分新增、修订、状态变化和确认 tombstone。分页中断、重复页、乱序修订、服务重启、429、超时和迟到结果均从已确认检查点恢复；没有新条目、未运行、鉴权失效、部分读取和失败分别呈现。
- 当前以鉴权 SSE 主动交付变更并唤醒桌面接收器，但服务端 `delivery_change` 和签名游标仍是权威；断线后使用同一游标协议补发，只在本机事务提交成功后确认新游标。服务不可用时，本地文件、既有来源镜像、任务、文档、研究和 Lib 继续可用。

### 4.3 鉴权、安全与可退出

- 最小跨网络切片先实现自部署首次配对与有 scope、可撤销的设备令牌，正式模式不以“localhost 所以无需鉴权”为前提。官方托管身份方案确定后，桌面客户端采用授权码 + PKCE 和短期 access token；在此之前不为假想账号体系实现完整登录。租户从服务端验证过的身份得到，不接受客户端任意指定。
- scope 随切片增加，至少区分来源读取、来源配置、触发刷新、正文读取和 edge ingest。所有服务查询在 repository 层强制租户范围，并以两租户同源、私有来源和越权 ID 做集成测试。
- 官方 API/OAuth 可在用户明确授权后由服务端保管；必须复用本机浏览器登录态的来源通过可选 `source-edge` 执行。edge 只在服务签发的作业和范围内取得响应，先移除 Cookie、认证 header 与未获准字段，再提交平台原生的最小载荷；服务端连接器负责 schema 校验、规范化、分页确认和条目入库。edge 没有独立调度或游标权威，也不把桌面业务层重新变成平台适配器。
- URL 获取在隔离 worker 中执行，限制协议、重定向、响应大小、超时和内外网地址，防止 SSRF；第三方正文始终是不可信输入，不能成为服务器指令。凭据、token、Cookie 和未获准正文不得进入日志、错误消息、用量事件或任务快照。
- 提供来源关注和必要历史的可携带导出，并分别实现断开平台连接、删除远端采集数据和撤销设备。自部署升级需要迁移、备份/恢复和回滚说明；源提供方或托管方更换后，本地已消化资产仍可读取。

### 4.4 为付费订阅保留什么

- `service_entitlement` 只描述可用连接器、关注数量、刷新频率、保留期和可选处理能力；业务逻辑预留内部 policy seam，不硬编码套餐名或支付平台 product ID。4B 使用默认 allow 策略且不暴露 entitlement API；4E 才冻结权益接口并接实际账户策略。
- `usage_event` 使用稳定事件 ID 幂等记录请求次数、取得字节、浏览器/媒体处理时长等实际成本维度，先用于测量。额度执行留到 4E；届时拒绝必须返回稳定错误且不破坏已有数据，自部署策略也走同一接口。
- 当前不选择支付渠道，不实现下单、续费、退款、税务、Webhook、套餐页或复杂运营后台。接入收费前单独验收租户隔离、凭据轮换、限流、审计、保留策略、数据导出/删除和真实单位成本，再确定套餐与价格。
- 自部署和未来官方托管保持同一客户端契约；本地基础工作台不强制依赖官方托管。服务器可以先是一个代码库中的 API/worker 两种进程角色，不为了“可订阅”提前拆成微服务。

## 5. AI 与协作底座先立住的规则

1. **任务归属**：项目、任务、成员运行、工具执行与产物都有稳定 ID。共享的是有效目标、必要资料、已确认判断与成果引用，不是所有项目和完整聊天的混合上下文。
2. **真实协作**：稳定成员可委派专项工作、向其他成员追问、接收修正并引用对方成果。委派信箱记录发起者、接收者、目标版本、问题、依赖、结果与处理状态；SDK 调用与信箱记录对应。是否参与由实际任务决定，不固定三人轮流发言。
3. **目标修正**：Y 的否定或修改产生新目标版本；系统确定受影响的任务，停止或使其失效，并重新调度。旧版本的迟到结果可留作历史，不能自动进入当前结论或覆盖当前成果。
4. **状态可信**：分别记录运行中、等待工具/成员/用户、暂停、失败、完成与待核实。界面总结基于已收到的事件，不生成百分比假进度；完成必须有可读取的成果和执行证据。SDK 的流式事件是输入，不直接等同于产品完成状态。[流式事件](https://openai.github.io/openai-agents-js/guides/streaming/)
5. **会话与恢复**：实现 SQLite-backed `Session`，同时保存产品自己的事件与检查点。SDK 会话历史用于后续模型轮次，不代表断电后可自动恢复任意正在执行的工具；可序列化的运行状态按 SDK 实际支持处理，其余从已完成边界继续。[Sessions](https://openai.github.io/openai-agents-js/guides/sessions/)
6. **工具副作用**：调用前记录操作 ID、目标路径、输入版本和授权范围，调用后保存真实结果。写文件采用暂存、原子替换与版本检查；数据库和文件之间保留提交标记供重启核对。未知结果先检查现场，不自动重放可能已执行的初始化、写入或外部操作。
7. **授权与停止**：任务内常规判断和已授权操作持续推进，不反复让 Y 审批同一范围。新增外部动作或超出授权时再请求明确决定。停止传递到运行、子任务和可取消工具；不能取消的远端操作如实显示，并保存服务 ID 以便查询。
8. **本地可控**：模型与本机工具凭据保存在本机凭据存储，信息源凭据按第 4 节的服务端 vault / 本机 edge 边界处理，配置只保存引用。Agent 日志与默认追踪留在本机，显式关闭 SDK 默认远端 trace 导出；服务只记录其采集运行所需的最小审计信息。资料外发策略与预算限制预留统一入口，后续细化；这不免除当前的资料和工具授权范围。

## 6. 首版验收基线

下面保留首版各部分的完成定义，并标出当前状态；它不是要求从增量一重新开发。

### 此前信息源实施顺序（已由新阶段 A–E 取代）

1. 冻结 `source-contract`、稳定 ID、内容覆盖、数据权威和凭据位置；在桌面建立 `SourceGateway`，使工作台与 Agent 不再依赖任何平台实现。
2. 用最小服务切片贯通公开 URL：`source-service` 完成设备认证、持久 refresh job、内容修订和主动 changes 交付，桌面保存远端修订与游标。本机独立进程/容器链路已实现；独立主机 TLS 和运维验收待完成。
3. 在最小切片上加入连接、来源关注和调度，再用服务端 OAuth/API 或 `source-edge` 接通一条真实持续平台来源；当前抖音证据较多，优先验证但不锁死。
4. 桌面增量同步、离线镜像、独立 Radar 阅读及自动团队主题消化已实现并通过确定性纵向测试；下一步完成真实模型批次验收、用户修正回写与跨任务复用。
5. 后续在真实成本和使用价值可测后做托管前加固与 entitlement/usage 验收；支付和套餐另立决策。

项目反馈、Agent 运行恢复和产物质量不依赖信息源主线，可并行推进；并行不允许跳过上述信息源内部依赖，也不把新平台逻辑写回本地 `sources`。

4A–4D 是首版信息源体验的交付门；4E 是未来官方托管订阅上线门，不阻塞首版本机工作台与自部署服务验收。首版只需保留 `tenant_id`、内部权益策略 seam 和用量事件扩展点，不提前实现 4E 的公开接口或商业运行能力。

### 增量四：独立信息源服务、信息吸收与 Lib 复用（本地 Lib 已实现；4A–4B 部分实施，4C 的关注/调度与 4D 的接收、自动团队消化及主题阅读已实现，修正与复用闭环待实施）

- **4A 契约与迁移切口**：建立最小 `source-contract`、`SourceGateway` 和旧来源 ID → 远端 provenance 映射。已有任务材料、成果、引用和 Lib 原样可读；兼容层只读已有正文快照并补 ID 映射，绝不为旧 URL 发起网络请求。所有新 URL 和重新取得正文都走服务，禁止双写。本地文件和粘贴正文归 `materials`，不迁往服务。
- **4B 公开 URL 最小纵向切片**：交付 API/worker、最小 PostgreSQL migration、租户作用域、设备配对、健康/就绪、持久 refresh job、租约/重试/限流、item revision 和 changes cursor；同时把当前公开 URL/GitHub 路径迁到服务，并让桌面完成实际同步。连接管理、定时关注、edge、导出和付费权益不阻塞这条 canary。开发环境可一条命令启动；交付验收须部署到独立主机或 VM，使用持久 PostgreSQL、secret 管理、TLS 和明确的备份位置，桌面不能访问其文件系统。
- **4C 持续与真实平台来源**：在 4B 上增加 connector connection、`source_follow`、重新授权、分页 checkpoint 和可配置调度，再接一条真正的持续平台来源。知乎官方入口、抖音和 Grok Build 的 X 能力按真实可取得内容比较；AIGCLINK 只作发现线索，结论回原始来源。每个连接器独立记录授权、列表、全文/转录/画面、历史范围与新增范围，不能因接口可调就标为完整可用。
- **4C 补充——抖音候选路径**：已观察到收藏页真实 POST 返回 HTTP 200、`status_code: 0`、`aweme_list`、`cursor` 和 `has_more`，两份成功响应的游标不同，请求体有 `count: 10`；尚未完成程序采集、修改游标后的签名重放或全量导入。服务端负责作业、分页状态、schema 校验、规范化和交付；如需复用用户正常登录的浏览器会话，由 `source-edge` 在明确授权下监听网站正常加载的 JSON，移除认证信息和未获准字段后上传平台原生最小载荷，Cookie 不离开本机。DOM 仅备用，不让模型逐条翻页。[当前验证记录](参考/抖音收藏接入验证.md)
- **4D 工作台闭环**：Radar 从服务同步指定与预置来源；服务端按外部 ID、内容 hash 和 revision 保证采集/投递幂等，本机只做近似内容的显示折叠、主题合并、与 Goal/Project/Lib 对照、相关性说明和新证据保留，不改变服务端权威 ID。可从知识点发起团队任务；用户修正回到本地判断和对应资产，来源读取/过滤状态与正式采纳/验证状态分开。
- **4E 托管准备（不阻塞首版本机体验验收）**：用至少两个租户验证隔离和额度拒绝，用自部署与托管配置运行相同契约测试；完成凭据轮换、审计、保留/删除和备份恢复演练。这里只验证未来可安全提供订阅服务的底座，不把支付或商业发布列为首版完成条件。
- **验收**：独立服务器和服务进程重启、桌面离线、分页中断、重复/乱序交付、429、鉴权过期和部分正文后均能恢复；分页重启不重复入库，列表缺失不当作删除，标题/描述不冒充全文或完整视频理解。至少一条真实平台来源完成“服务取得 → 桌面同步 → 团队消化 → 关联已有 Lib → 形成成果 → 另一任务复用”，且能回到具体 item/revision；本地工作台在服务不可用时仍可处理已有资料。若启用定时计划，关闭桌面后服务仍按计划执行并留下真实时间与失败证据；未启用时只称对已产生变更的推送/补齐，不称自动持续监控。

当前 4A–4D 实施证据（2026-09-12）：仓库已成为渐进式 workspace，`packages/source-contract` 冻结运行时 Zod 契约与 OpenAPI，`services/source-service` 可按 `api` / `worker` / `all` / `migrate` 角色独立启动；服务端 PostgreSQL 是 source、follow、job、item、revision 和 change 的唯一权威。worker 不取得配对/token/cursor secret，API 可在首次配对后关闭 bootstrap 端点；服务按验证后的 token 在 capabilities 返回租户，桌面校验配置并写入完整 provenance。用户 URL 关注和默认服务器推荐源共用租户化持久调度，但保留独立 origin；条目以 `external_item_key` 支持一来源多条内容，当前公开页使用 `page`。新 URL 网络请求只经 `HttpSourceGateway`，桌面原 URL 网络实现已删除；公开 URL 安全边界、响应字节上限和契约校验在服务与客户端均生效。鉴权 SSE 使用 PostgreSQL 通知唤醒并按签名游标取得权威变更；ytriple 验证修订内容/hash/覆盖范围后，将远端 revision、Radar 本地状态和游标原子提交。新修订由本机团队自动建立隐藏批次；Store 原子锁定 item/revision，运行时与 Store 双重验证完整分页读取、输入覆盖、证据/修订/上下文和幂等发布，普通回复不能进入 Radar；失败保持未读、页面可见并只允许显式重试。Radar 以当天主题理解为主，独立保留历史、原始信号、筛选理由和来源管理；Why it matters、多来源证据、Goal/Project/Lib 对照、分歧、缺口及历史锁定正文均来自持久化结果。真实 PostgreSQL + HTTP/SSE + worker + 桌面集成测试已验证默认推荐首次取得、定时修订推送、在线接收、离线补齐、重开续传、无重复和用户源暂停/删除；自动消化链路当前由确定性模型纵向测试验证，真实 Gemini 批次必须另记。尚缺的交付门槛包括：用户修正作为一等本地记录并触发新判断、修正后的判断进入 Lib 和另一任务复用、桌面 safeStorage 配对与设置界面、待处理写入的本地恢复、旧 URL provenance 兼容映射、设备撤销、来源级并发/限流与完整失败矩阵、独立主机/VM 的 TLS/secret/备份/重启演练，以及首条真实平台来源。因此本轮记“本机持续监控 → Radar 诚实接收 → 自动团队消化 → 结构化主题阅读”的确定性切片完成，不记 Radar 价值闭环或信息源首版整体完成。

## 7. 配置与缺失项怎样处理

| 缺失或不确定项 | 开发处理 | 真实交付条件 |
| --- | --- | --- |
| 模型 endpoint、model ID、凭据或服务权限 | 先完成配置结构、适配器和错误状态；按现有获授权配置选择一条真实连接开展主线 | 每个配置分别测文本、流式、工具、多轮工具结果、取消和错误处理；不能仅凭“连接成功”标为可协作 |
| Gemini 原生与 SDK 的映射 | 经 `Model`/`ModelProvider` 或经核查的官方适配扩展接入；保留提供商特有能力 | 先测工具结构、消息往返及流式事件，再定适配细节；不能假设兼容模型支持全部 SDK 能力 [模型接口](https://openai.github.io/openai-agents-js/guides/models/) |
| 本机 Ark 配置具体形态 | 由独立适配器读取获准的配置引用，核查接口类型及模型，不把“本机配置”解释成本地推理 | 实际请求成功并通过所需能力探测；不输出或复制密钥到仓库 |
| Google Deep Research 权限或服务不可用 | 保留独立能力入口和清楚状态，研究员仍可利用现有资料与已接通搜索完成研究 | 专项服务单独实测；普通模型研究不标为 Google Deep Research |
| 信息源服务未配置、不可达或协议不兼容 | 桌面保留服务地址、设备配对、能力协商与离线镜像；本地文件/粘贴、已有任务、Lib 和成果继续可用 | 自部署服务通过独立启动、健康/就绪、契约兼容、迁移和重启恢复；界面显示最后成功同步时间与真实故障，不把本地 URL 回退当成服务成功 |
| 平台账号、CLI、分页或全文尚未验证 | canonical 连接器、schema 与规范化只在 `source-service` 开发；`source-edge` 仅实现必要的平台响应捕获和脱敏传输。仍允许用户在本机导入文件或粘贴正文 | 来源状态分未配置、待验证、部分可用、已验证；授权、收藏列表、正文、视频转录与画面分别计证据覆盖，一个平台成功不代表其他连接器可用 |
| 平台需要浏览器登录态 | 使用有 scope 的 edge 配对和单次/限定范围授权，Cookie 留在系统凭据或浏览器中；edge 只上传剥离认证信息后的获准平台最小载荷，由服务校验和规范化 | 核查断开、过期、取消、迟到结果、重复分页和日志脱敏；不得要求用户上传完整浏览器配置或把登录态当通用服务器凭据 |
| 未来托管额度或付费状态 | 首版只留内部 policy seam 与用量事件扩展点；到 4E 再实现 provider-neutral entitlement 查询和幂等 usage 账本，自部署也通过同一接口返回本地策略 | 两租户隔离、额度拒绝不损坏数据、导出/删除与真实单位成本通过；支付接入和价格另行决定，不能因字段存在宣称订阅已上线 |
| 全部模型连接暂缺 | 完成界面、持久化、工具及自动化验证，开发夹具明确标记且不进入用户真实任务 | 至少一个获授权的真实模型完成增量一之前，不宣称 AI 底座已交付 |

当前 Gemini 已实测可用；DeepSeek 尚缺可验证的账号配置，Ark 的当前 Coding Plan 账号权限不可用。各连接独立显示状态，不因为环境变量存在或另一渠道成功而标为 ready。

测试只为关键风险设验证：状态转换、版本冲突、恢复与工具幂等用确定性测试；信息源增加 OpenAPI provider/consumer 契约、跨租户授权、变更游标、SSRF、日志脱敏、自部署升级/备份恢复和服务进程独立性测试；模型与每个来源用小规模真实集成验证；窗口交互和产物打开做端到端检查。测试替身证明工程行为，真实调用证明能力，两类结果分开记录。
