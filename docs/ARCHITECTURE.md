# 架构

本文记录由 [产品定义](PRODUCT.md) 确定的系统边界、采用的技术方案、数据归属和工程约束。实现任务与验证证据由 [执行计划](PLAN.md) 跟踪；技术已选定不等于实现已验证。

## 技术方案与落地边界

| 层次 | 采用方案 | 取舍与边界 |
| --- | --- | --- |
| 桌面与界面 | Electron 44、React 19、TypeScript、electron-vite | 一个桌面窗口内三工作面；主进程代理服务连接和本地可选模式，sandbox renderer 通过窄 IPC 接口调用 |
| 独立服务 | Fastify 5 / Node | 桌面通过类型化 HTTP 接口使用服务，传输层可供后续手机复用；模型密钥只在服务端；P1 验证单用户自部署连接，账户／权益和信息订阅业务按后续阶段开发 |
| 数据 | Node 内置 SQLite，执行端数据目录内独立数据库，模式版本迁移 | 避免额外原生驱动 ABI；工作、运行、事件、成果版本和草稿持久化，写入事务及版本比较保护并发；本地与服务端同一 Repository，草稿／布局按设备保存 |
| 编排 | LangGraph.js 1.4 的 StateGraph；自有 TeamStrategy 契约封装 | 采用负责人规划、分工、交叉核查、汇合的有界图，任务由负责人按本次目标分配；最多一次定向返工、默认并发 2、默认每轮最多 8 次调用及 180 秒时限；不自建通用图运行时 |
| AI 适配 | LangChain ChatGoogle 与 ChatOpenAICompletions | Gemini 原生、显式 OpenAI Chat Completions 兼容模式；默认候选 gemini-3.8-flash，模型名可配置，凭真实可用性验收；所有角色初始独立调用同一模型，本地模式允许角色级模型覆盖，P1 服务端仅允许当前管理员配置的模型 |
| 凭据 | 服务端环境变量；本地可选模式和设备令牌用 Electron safeStorage | renderer 只知道是否配置，不取得已保存密钥；不记录原始请求头、SDK 错误对象或模型私有 reasoning 块 |
| 验证与产物 | Vitest 核心／存储回归，Playwright Electron 实际 UI 检查和服务 API 集成检查，arm64 本地应用打包 | 替身流程与真实模型调用分开；未签名本地开发产物不冒充正式分发包，真实提供方差异如实记录 |

选择 LangGraph 的原因是需要可控图步骤、并发、条件返工和可替换流程；编排由自有应用服务掌握，不把团队状态交给某家托管 Agent 服务。P1 无需为不同角色选择不同厂商，也不根据头像数量认定多 Agent：每项委派必须有独立职责、限定上下文和实际返回，被负责成员核查或采用。

P1 使用应用数据库恢复工作与已完成记录。进程中断后，未确认运行标记为中断／结果未知，由用户继续发起新运行；不自动重放未知外部请求，也不宣称支持跨崩溃的精确 LangGraph 节点续跑。独立策略可在不改页面和持久化身份的情况下替换；角色／方法／模型配置按运行快照保存。

选型依据：[LangGraph 工作流](https://docs.langchain.com/oss/javascript/langgraph/workflows-agents)、[Electron 进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)、[SQLite API](https://nodejs.org/api/sqlite.html)、[safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)、[Gemini 模型](https://ai.google.dev/gemini-api/docs/models)。具体补丁版本以 package-lock.json 为准。

## 系统、模块与数据归属

默认服务模式由独立服务器维护工作、运行、过程和成果，统一配置模型；桌面通过服务接口访问工作空间，后续手机复用该接口。本地可选模式在桌面主进程运行相同 AppService 与 Repository，数据独立。模式切换不迁移资料，也不承诺离线副本或双向冲突同步。后续雷达来源、抓取与订阅放在服务端业务模块，客户端订阅阅读；不把抓取定时器放入手机或桌面渲染进程。

| 逻辑责任 | 维护的状态与公开入口 | 跨边界约束 |
| --- | --- | --- |
| 工作与运行 | 工作身份、有效目标、运行状态、过程与成果引用；提供开始、纠正、继续、停止、记录与读取入口 | 维护运行事实的持久状态，三窗口和各业务入口引用同一工作；能力返回先关联所属运行，再判断对当前目标是否有效 |
| 协作编排核心 | 默认团队流程、成员责任分配、委派与回信处理、多视角交流、汇合与修正策略；输出带归属的公开分析和下一步动作 | 核心独立于界面、软件／媒体业务和提供方；通过工作入口保存实际运行记录，通过能力入口调用模型与工具，不直接改项目正文或成果存储 |
| 项目、来源与资产 | 项目／作品归属、材料及读取范围、来源版本、资产索引和正式资料位置；提供导入、查找与受限读取入口 | 项目权威正文仍在项目内；索引、快照与可复用副本具有不同用途，查找结果不等于正文访问授权 |
| 成果与反馈 | 成果身份、版本、编辑基线、交接及使用证据、反馈采纳范围；提供修订、比较、导出、关联证据与采纳入口 | 协作提出的修改通过成果入口处理；不能覆盖未知外部改动，也不能把局部反馈直接变成全局规则 |
| 模型与能力接入 | 提供方能力、Skill 版本及依赖、实际调用与返回、用量和失败信息；提供能力查询与受控调用入口 | 不假定兼容接口支持所有专项能力；Skill 和外部材料不能自行授予权限，提供方状态不能冒充本地工作完成 |
| 委托与调度 | 持续委托、触发条件、执行位置、有效方法版本与触发历史；通过工作入口发起和核对运行 | 不另建聊天或成果体系；重试前核对已有运行，暂停委托与停止本次运行是不同操作 |
| 导航、处置与通知 | 工作选择、窗口布局、阅读位置，以及原业务事件的提醒偏好与处置展示 | 首页、项目和定时任务读取原对象状态；已读、静音和暂缓不能反向改写业务结果 |

资料读取、发往提供方、写入本地目标和远端委托使用同一套授权判定；导航、Agent 委派和 Skill 加载都不能绕过它。凭据不进入普通成果、公开过程和资产导出。具体权限粒度和持久化方式在相应实现前确定。

### 模块依赖与状态维护

采用模块化应用服务：界面通过应用入口发起动作，业务模块维护自己的状态，文件系统、模型、工具和远端服务通过适配入口接入。客户端界面不直接持有提供方密钥、不直接改业务存储；项目、雷达和资产复用协作核心，协作核心不依赖某个页面或某类项目的专用流程。进程数量与具体库不由逻辑模块数量决定。

实际运行状态由工作与运行模块维护；当前阅读对象、布局和编辑草稿由界面状态维护。草稿保存与正式成果修订分开处理。关闭工作面不等于取消运行，返回结果也不能直接触发页面跳转或覆盖编辑内容。

反馈模块记录采纳及依据，改变项目标准或方法版本时调用相应维护者的入口；不能跨模块直接改内部状态。公开类型和接口形成后，以依赖检查、类型检查与边界测试约束这些关系，不继续复制接口正文到文档。

### 分阶段融合与替换

阶段范围不构成独立产品架构。下表区分长期保留的责任和有明确适用范围的初始实现；后续接入前补具体迁移，不预建没有行为的业务模块。

| 当前基础 | 后续如何融合或替换 | 不得丢失的事实与边界 |
| --- | --- | --- |
| 稳定导航、首页开始与工作查找 | 雷达、项目、资产、定时任务在原入口内逐步开放；首页增加原对象的真实状态投影，状态说明页被业务正文替换 | 导航不按阶段重组；首页不是各模块副本；工作台不绑定某个示例或业务页 |
| Work、Run、Material、Artifact 与版本 | 通过关系及递增模式迁移加入项目／作品／议题归属、资产复用和外部来源；继续引用原工作，不复制会话 | 原 ID、目标版本、引用、实际输入与已有成果；浏览和归属改变不等于上传授权 |
| 三面工作台与成果控制器 | 各业务进入共同工作台；Markdown 阅读／编辑在同一成果身份上扩展格式、比较、导出与交接能力 | 当前阅读版本、手工草稿、冲突基线和准确来源；不因换编辑器要求重建成果 |
| TeamStrategy、模型适配与运行快照 | 在原策略契约后升级流程、增加能力；先解析领域及工作配置，再固定为本轮快照 | UI 不硬编码角色数或算法阶段；历史身份、实际方法和能力版本不被新配置改写 |
| 内置 Skill 配置 | 当前配置承接少量方法；资产中的能力注册与版本管理接入后，设置负责默认选择，执行解析对应版本，不建立两份竞争正文 | 已有方法内容、ID、版本及运行时实际输入；完整导入与资产管理仍须专项实现 |
| AppService、服务协议与桌面适配 | 雷达来源、订阅处理及调度放服务端业务模块；手机后续通过共享客户端使用同一服务对象 | 模型密钥留执行端；页面不自己抓取或调度；不把手机实现提前塞进桌面流程 |
| 单拥有者令牌、服务地址区分空间 | 适用于私有自部署；正式托管需接入身份、明确 workspace 范围及可吊销设备凭据，桌面地址命名空间需迁移为明确空间身份 | 用户数据、设备草稿与空间隔离；不能把当前单用户模式直接扩为多人共用公网服务 |
| 桌面待核对提交与中断记录 | 当前未知回执保留请求、核对既有运行且不自动重发；持久调度接入前补持久请求身份与去重协议，替换核对机制时迁移已有待核对记录 | 已接受运行、未知状态、版本和用量；不能把当前 UI 匹配规则冒充可靠后台调度 |

判断改动是否能进入当前基础时，需明确其状态维护者、现有公开入口和后续接入位置。只服务验收的替身、临时数据和验收包属于测试设施，不能成为生产默认内容；临时生产实现必须写清适用范围和替换时的数据接续。


### 服务连接与多端边界

`src/application` 统一工作动作及运行生命期，`src/server` 提供经过校验的 RPC 和增量变化通知，`src/client` 提供无 Node 依赖的 HTTP 客户端；桌面可选本地模式直接复用应用服务。桌面 IPC 和服务 RPC 都只开放明确动作，不接受任意 SQL、文件路径或模型调用。

P1 是单用户自部署服务，每个服务数据目录是一个私有工作空间，Bearer 访问令牌只代表该空间的拥有者。默认仅监听回环地址；其他设备在可信局域网开发时可显式开放监听，公网连接要求 HTTPS。它不是多租户账号／订阅系统；正式托管前须实现租户范围校验、设备令牌吊销、用量权益和部署运维。服务端不接收客户端修改提供方、密钥或任意模型地址。

服务模式只上传用户在该服务工作中提交的文字和明确导入的文件。切换地址重新选择空间，工作身份带服务上下文；各设备的草稿与阅读布局分开保存，成果版本共同维护并检查编辑基线。断线后可重新读取已落盘事实，取消不能保证提供方已终止，未知请求不自动重新提交。服务重启标记未完运行中断。

手机 App 在桌面体验完善后再开发。后续复用同一工作、过程与成果对象，以适合小屏的入口访问；当前保持客户端传输层无 Node／Electron 依赖，不提前在桌面业务里嵌入手机专用逻辑。

## 关键工程决定

### 协作编排核心可独立升级

团队如何组织视角、决定分工、处理返回、发起追问、汇合判断和结束处理，由独立编排核心承接。业务提供目标、材料、领域要求和可用能力，界面发送用户意图并展示实际事件；业务页不各自实现一套 Agent 循环。该边界用于独立测试和持续替换算法或流程，不要求额外拆成远端服务。

编排策略、角色定义、成员能力配置、Skill 和模型适配分别维护。调整团队角色或更新能力通过明确配置生效，记录相关版本与生效范围；正在进行的工作在明确边界采用变化，历史分析仍保留实际使用的身份、方法和能力版本。升级不能静默重写历史、扩大授权或使已有成果失去引用关系。

编排核心接受工作与目标版本、材料引用、团队及方法配置和有效能力范围，产生委派、成员公开分析、步骤关系、修正及成果提案等结构化输出。存储、权限和真实调用通过约定入口完成；输出契约能同时被界面消费和独立检查。先实现真实默认团队流程，再以相同契约验证后续策略，避免将初版流程写死在页面或角色提示词中。

### 过程记录同时承接用户学习

步骤关联实际问题、方法、要求、输入依据、成员贡献、结果和后续修正。多轮讨论关联稳定的工作对象与步骤关系，使用户能从结果中的不足回到相应处理环节，并追踪修正后的变化。步骤按真实执行与公开分析形成，不要求每项任务填同一组栏目，也不能凭事后归纳伪造当时步骤。

过程修正沿用 `revise` 意图与 `event` 引用；没有现有成果也可处理，有成果则保留原版本基线。只有 `artifact` 引用的选段才能约束成果原文替换，过程选段作为待纠正判断提供上下文。核心不依赖数据库分配事件 ID；同轮的分工、核查、返工与汇合可通过内部事件键表达关联，由 Repository 在写入时解析为已存在的真实事件 ID，客户端继续读取统一 `relatedEventIds`。

成果依据按版本 `runId` 定位运行快照、输入材料和已记录公开分析；手工版本通过 `baseVersion` 标明继承基线，不宣称经过新的模型核查。这一关联不等于每个句子已经具有精确引用。

流程草案由成果与反馈入口从已记录方法、修正及使用证据中整理，保留适用范围和版本；采纳或试用通过能力维护入口承接。Agent 的自主学习机制尚未选定，本阶段保留可追溯记录、反馈和可升级配置，不预建自训练或自动改写规则的系统。

### 对象与版本先于页面

工作、运行、成果版本、材料来源和持续委托具有可区分的身份。首页、雷达、项目和三个窗口通过引用定位对象，不各自维护一份有效目标或成果正文。身份的具体存储格式由实现确定。

处理输入需能追溯到当时有效的目标、材料范围和方法版本；成员汇报、结果和后续反馈关联到这些输入。当前视图与历史记录分开，晚返回或重放的旧记录不能自动成为当前结论。

运行输入固定不等于授权永久有效。每次实际读取、发送或执行前检查当前授权；子任务的资料、工具与动作范围受父任务授权限制，不能因委派、重开或切换提供方而扩大。运行请求与成员关系须有明确终止条件、调用限制和失败处理，不能靠无限对话循环实现协作。

从第一阶段起为持久化数据保留模式版本和升级入口。新增业务可以扩展关系，但不能把重建索引当成恢复原资料，也不能让一次升级静默丢弃既有工作、成果或反馈。当前由 Repository 的 `PRAGMA user_version=1` 记录模式；初始化事务创建结构，遇到高于程序支持版本的数据库明确拒绝打开，禁止自动降级或重建。后续变更在同一入口添加递增迁移及原数据保留回归。

### 编辑、交接与反馈各自保留依据

成果修订以用户正在操作的版本为基线；基线已变化时先保留差异，再处理冲突。交接、使用和验证证据指向准确版本，不用一个线性“完成”字段表达所有事实。软件项目的正式文件、成果草案和指定反馈文档按 PRODUCT 第 7.2 节区分，不能把草案修订显示成正式文件已经回写。

已采纳反馈带有适用范围与来源，后续使用可以追溯；方法升级不自动替换长期委托正在使用的版本。保留修正关系与历史证据，不把总结文本当成新的事实来源。

### 运行事实与公开分析分开记录

运行事件记录实际委派、调用、失败与取消结果；公开分析记录成员主动给出的判断和依据，二者关联但不能互相替代。没有收到公开分析时标为缺失，不能通过日志事后伪造。

停止请求与实际停止结果分开；恢复时先核对已有运行和远端结果。重复触发、事件重放与未知远端结果的防重复机制，必须在接入调度前验证。不能仅依靠界面按钮变灰证明执行可靠。

### 数据独立于可选服务

已保存的本地资料、成果和必要关系不依赖官方订阅有效性。备份与恢复保留用途及版本关系，遇到同名对象或外部变动不静默覆盖。缓存和索引不能成为找回用户原始资料的唯一依据。

### 项目初始化与持续管理分开

初始化入口接收已确认产品材料、项目位置、适用 Policy 与模板版本，生成有实际内容的目录、规则、文档及交接材料；为未决工程问题保留明确接续位置。模板版本与本次生成内容保持关联，初始化结果用于专业开发工具接手，不授予后续持续改写整个项目的权限。

项目读取入口覆盖获授权的项目整体内容，维护已读内容及版本、未读和不可读范围；文档、源码、配置、测试和已有结果共同支持项目理解。可分批读取并形成分层理解，后续比较变化后更新受影响部分；目录清单或摘要索引不能代替实际读取覆盖。模型调用只获得当前处理所需且获准的内容，不把全面本地读取等同于整库上传。

既有项目的建议写入入口绑定该项目固定建议文档，维护新增建议、依据和原内容的关系；外部版本冲突沿用成果的基线检查。其他项目文件通过读取入口访问。ytriple 自身工作数据的保存与外部项目写入分别处理，不能用一次状态刷新绕过该边界。

## 开发与验证入口

工程入口：`src/shared` 类型／输入校验；`src/core` 独立策略；`src/providers` 模型协议；`src/storage` SQLite；`src/application` 动作与生命周期；`src/server` 服务；`src/client` 共享传输；`src/main` 与 `src/preload` 桌面安全边界；`src/renderer` 桌面视图。允许依赖由 `scripts/check-boundaries.mjs` 自动约束。

- `npm ci` 安装锁定依赖；`npm run dev` 启动桌面，`npm run server` 独立启动服务。
- `npm run check` 执行类型、模块边界、核心／存储／服务／模型协议回归及桌面构建；`npm run test:ui` 实际操作 Electron，使用隔离提供方替身。
- `YTRIPLE_LIVE_TEST=1 npm run test:live` 经授权后发起真实调用，只使用内置虚构材料与临时库，记录团队及跨设备继续结果，不读取用户项目。
- `npm run server:build` 生成独立 Node 入口；`npm run package` 生成 Apple Silicon 桌面 `.app`。
- `YTRIPLE_ACCEPTANCE_MODE=controlled npx tsx scripts/desktop-acceptance.ts` 为人工桌面验收准备隔离服务、独立数据目录及独立名称的 macOS 包，不自动操作界面或创建工作。获准真实调用后用 `YTRIPLE_ACCEPTANCE_MODE=live YTRIPLE_LIVE_TEST=1` 运行同一入口；模型密钥只在服务环境中，生成的临时回环服务令牌不进入源码或日志。用实际桌面操作串联目标、协作、修正和恢复。

运行限制由 `src/shared/validation.ts` 校验，UI 不能越过接口上限。P1 默认值、最高可配置范围与实际已用量分开：调用数默认 8、最高 16；总时限默认 180 秒、最高 300 秒；工作容量与连接检查也在 AppService 中限制。公网生产部署、订阅权益和长期运行恢复尚须后续专项实现与验收。

验证分工：跨入口状态、版本冲突、范围隔离和恢复行为用可重复检查验证；三窗口联动用实际 UI 操作观察；模型接入与成员协作用获授权的真实调用验证；外部使用效果由准确交接版本及真实反馈验证。具体场景选择与证据只维护在 PLAN。
