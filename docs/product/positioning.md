# yTriple Positioning

## Status

Active。本文件是所有新契约文档的共同前提。所有 `docs/**/v1-*.md` 已标记 superseded，其中的「小团队 / 团队协作」用户假设不再作数。

## One Line

yTriple 是给**一个人**用的 AI 团队工作台：本地跑得起来，一个人指挥一支可配置的 Agent 团队，把模糊输入变成能直接用的交付物。

## Target Users

产品只服务两类单人用户。所有取舍以这两类人为准。

### A. 个人开发者

独立开发者、side project 作者、小工作室里唯一写代码的人。

- 没有产品经理，也没有调研同事，想清楚需求这件事只能自己干。
- 真实痛点是「想法到能交付给 AI coding agent 执行的 PRD」之间那段空转：想法在脑子里和聊天记录里反复打转，落不成文档。
- 交付物必须可执行：`prd.md` 要干净到可以直接喂给 Cursor / Claude Code 当输入。
- 同时需要持续的技术与竞品动态输入，判断「这个方向还值不值得做」。

### B. 个人自媒体工作者

独立写作者、独立 UP 主、newsletter 作者、单人内容账号运营者。

- 真实痛点是**选题供给**和**信息过载**：既怕漏掉行业动态，又不想每天刷两小时信息流。
- 需要的不是原始新闻，而是加工后的判断：这条为什么重要、能从什么角度写、还有没有热度窗口。
- 同样需要把内容策划、专栏规划这类模糊想法收束成结构化方案。

### 两类用户的共同点

这些共同点直接决定架构约束：

- **一人多角色。** 产品里不需要角色权限、审批、评论、@ 人。
- **成本敏感。** 一次任务花几块钱是可接受的，花几十块不是。预算约束必须是一等公民（见 [Provider 契约](../contracts/provider-contract.md)、[Agent 团队契约](../contracts/agent-team-contract.md) 的子 Agent 预算约束）。
- **时间碎片化。** 不接受长表单和前置审问，首稿优先「方向对」而不是「完整」。
- **隐私敏感。** 本地代码和素材不愿上传。工作区读取必须是桌面本地能力（见 [运行时边界契约](../contracts/runtime-boundary-contract.md)）。
- **自带模型 key 是常态。** 很多人已经有 Gemini / DeepSeek / Ark / OpenRouter 的 key，产品必须允许 BYOK，而不是强制走托管额度。

### 两类用户的差异

| 维度 | 个人开发者 | 个人自媒体工作者 |
| --- | --- | --- |
| 主要交付物 | `prd.md`（可执行需求） | 选题与内容方案 |
| 主要消费形态 | 一次性任务，用完即走 | 持续信息流，每天回来 |
| 雷达加工口径 | 技术影响、可用性、迁移成本、竞品动作 | 选题角度、受众钩子、热度窗口、可讲的故事 |
| 桌面依赖 | 高（要读本地代码工作区） | 低（更多在手机上消费） |

这条差异是雷达服务分流加工口径的依据，见 [雷达服务设计](../server/radar-service-design.md)。

## Product Principles

1. **默认路径零配置。** 不填任何设置也能跑完一次任务；配置只用于变强，不用于启动。
2. **单人默认预设优先于自由编排。** 团队可配置是底层能力，但用户日常面对的是 `prd.default` 那三个人（见 [Agent 团队契约](../contracts/agent-team-contract.md)）。
3. **桌面本地优先，托管是可选项。** 本地能跑完整核心；服务端提供常驻雷达、长任务和手机端接入。
4. **成本可预测。** 每个 Agent 槽位可以绑不同价位的模型，子 Agent 有硬预算上限，超预算是明确失败而不是静默烧钱。
5. **过程可见但结果唯一。** 过程材料在界面里看得见，默认交付物只有一个文件。

## Non-Users And Non-Goals

明确不服务的对象：

- 需要多人协作、权限模型、审批流的团队。
- 需要合规审计、数据驻留承诺、SSO 的组织客户。
- 需要深度咨询级研究报告的用户。

明确不做的能力：

- 团队协作、共享空间、评论流。
- Git 写操作与代码修改。
- 插件市场、可视化 agent builder。
- 修改用户工作区里已有的文件。
