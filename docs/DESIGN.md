# ytriple 视觉与交互方向

统一确认入口：[UI 与交互确认稿 v1](UI-BASELINE.md)。本文保留对应领域的详细规则。

2026-09-16。本轮收敛的视觉规范，纳入统一 UI 确认稿；页面逻辑见 [PAGES.md](PAGES.md)。

当前确定的方向：AI 工作台采用亮色，保留左侧汉堡菜单与可折叠全局导航、首页与当前工作中的底部输入入口，其他页面按上下文展开。此前石墨色方案不再作为候选主题。用户已认可亮色和雷达权重，但指出功能关系与交互不足；首页 `d2adb8aa8c6a452187f15f4ea1369b99` 仅保留为视觉参考，不冻结其中的区块和动作。界面首先遵循 [INTERACTION.md](INTERACTION.md) 与 [PAGES.md](PAGES.md)，必要时重做结构。

## 核心表达

一个明显的团队对话入口，必要时展开为沉浸式决策、过程、结果。产品辨识来自“读懂团队怎样协作、怎样改变结果”，不依赖装饰、成员数量或复杂管理界面。

普通入口保持低复杂度。首页以工作 Dashboard 呈现明显的输入与继续工作，并让雷达观察成为有实质内容的主要阅读区，待决事项保持清楚可达；雷达保留阅读主次；项目保留简短目标与当前交付。不同功能可以用输入框、上下文提问或继续工作操作进入同一工作，无需相同模板。

## 视觉尺度

- 首页版式变化程度约 6/10；动效强度约 2/10。功能简单不意味着同样大小的盒子、弱标题或大片无效留白，视觉节奏由实际工作内容决定。
- 首页信息密度约 5/10；沉浸工作约 6/10，空间用来读实质内容。
- 页面底色中性浅灰 `#F8F9FB`，侧栏 `#F3F4F6`，正文表面 `#FFFFFF`；采用亮色，不使用暗色大面积工作面。
- 正文深灰 `#20242C`，辅助文字 `#626974`，分隔线 `#E5E7EB`。
- 单一蓝色 `#4268C6` 限于主要操作、链接和必要焦点，不给正文、普通标题和提示统一染蓝。选中优先用中性浅底与字重，层级先由文字、间距和真实内容建立。
- 正文和界面采用 Geist 与苹方/Noto Sans SC 回退，正文 15–16px、辅助 13px、首页主标题约 30px、重点工作标题约 24px、区块标题约 18–20px。用中等和半粗字重拉开层级，软件界面不用衬线字体和装饰性等宽元数据。
- 留白基于 8px 节奏，主要页面间距 24–32px；对话框内边距约 20px，圆角 10–12px，其余控件 6–8px。优先对齐、分隔和留白，减少盒中盒。

## 入口与组件

### 边界使用规则

**用户明确禁止左侧亮色竖条这一视觉样式，适用于所有 UI 设计。** 导航选中、列表选中、引用、提示、警告、修订段落及活动卡片均不得使用；细左线、伪元素、渐变或阴影模拟的竖条同样禁止。也不能旋转成另一侧亮条或换颜色来变相沿用。此规则优先于早期稿和外部 UI 模板，旧稿中的相同样式不再作为可复用参考。

普通内容区默认无框、无阴影、透明背景，以标题、对齐和留白分组。文章、项目概览、成员贡献、流程步骤、设置分组不使用外层卡片再套内部卡片；不能把去掉的边框逐个换成浅色矩形。列表只在需要辨认行关系时使用极浅水平线，不给每行完整描边。

边界只承担操作或空间语义：输入与选择控件、上传落点、键盘焦点、模态对话框、成果文档表面，以及决策/过程/结果工作面之间的中性细分隔。工作面内部的消息、引用说明和贡献记录保持扁平。选中资料用中性浅底与字重，需要时附勾选或明确状态文字；普通提醒直接在相关内容旁说明，不使用左线或整块彩色提示卡。键盘焦点保留完整清晰的轮廓，不能因去装饰而丢失。

修订标记是版本信息，不是选中态。默认结果正文保持连续排版，可在段落旁用小号但可读的“已修改”文字；依据缺口在相关句子之后作普通文字注记。“比较版本”才显示明确的增删差异。禁止亮条、淡蓝/紫底、大圆角、闪光图标、蓝色小标题叠加成 AI 提示卡。普通正文不因 AI 生成而需要专门的装饰容器。成果修改入口统一为“让 AI 重新整理”（有选段时说明选段），回到原决策输入；不再增加正文编辑器、编辑草稿工具栏或手工合并弹层。

保留底部聊天入口的单一干净表面，其常用操作使用图标；页面其他次级操作按语义采用文字或轻按钮。验收时先看是否能凭文字主次和间距读懂分组，再检查输入、选中和工作面区别是否明确；不以边框数量代替信息层级。

首页底部常驻多行输入框，默认归属新工作，与上方继续已有工作的操作分开；主内容预留底部空间，浮动入口不能遮住信息。按用户要求，添加、交流对象、展开工作区和发送采用图标控件，解释放在悬停/聚焦提示与菜单；保留工作名称、引用及必要状态文字。展开工作区图标始终直接可见，不藏入菜单，也不冒充发送。具体功能和状态遵循 [COMPOSER.md](COMPOSER.md)。

首页不再使用固定的卡片模板。跨项目继续工作与高权重雷达阅读为主体，待决融入对应工作，底部输入明确为新工作。团队贡献归原工作过程，不在首页单列活动流；成果片段只为接续判断提供内容，不另设重复成果卡。首屏每个区域须能解释它对应的对象、当前用户判断和主动作，否则应合并或移出首屏。各内容共用对齐基线、字体和色彩，不能把自由排版理解成错位或重叠。

工作预览展示可读的真实成果片段与准确版本入口。内容所需的文档表面可以有边界，不能用假截图、倾斜纸张、头像堆、装饰线或虚假数字填充视觉。没有成果时显示该工作的实际问题与材料，不造一页假成品。作品、证据和成员贡献本身提供视觉内容。

成果入口融入原工作，避免重复的最近工作、最近成果与待办列表。无数据时按内容收简；留白负责聚焦，不让首屏下半部只是没有用途的空地。待决项按实际影响呈现，重点工作来自用户固定或可核查变化，不用生成的排序假装理解用户优先级。

上下文入口只说明实际已选材料、当前对象和必要限制；项目身份不是全量资料授权。长文阅读位置不被悬浮输入框遮住，项目对象不被大聊天历史取代。

发送后呈现轻量团队回复，保留继续输入与展开入口。未发送草稿也能直接展开；布局变化不建立永久空工作。处理过程、迟到结果和持久化均归原工作。

沉浸模式收起全局导航，保留退出、归属和必要操作。默认左决策、右过程/结果切换，可自由排列三个面；成员与窗口数量无绑定。

团队过程根据实际因果关联显示提出问题、分工核查、证据与限制、修订结果。只有有关联的贡献才用轻连接线，不能把普通时间顺序伪装因果；附有实际正文和成果入口，不做头像墙、空流程图或日志瀑布。

## 状态与动效

静态内容不循环闪烁或逐字播放。过渡只服务聚焦、切换与反馈，约 120–180ms，遵循减少动态效果偏好。新内容只提示，不抢焦点、布局或阅读位置。

点击目标约 44px，键盘焦点清楚。加载占位与实际内容尺寸接近；错误在所属对象旁显示并保留输入；空状态提供可执行入口，无需装饰插图。

状态用真实文字说明，不造完整度、置信度、在线人数或后台已保存声明。可用的能力和设计样例明确区分。

## Skill 的采用范围

参考 [Stitch Design Taste](https://github.com/Leonxlnx/taste-skill/blob/main/skills/stitch-skill/SKILL.md)、[Redesign](https://github.com/Leonxlnx/taste-skill/blob/main/skills/redesign-skill/SKILL.md) 与 [Minimalist UI](https://github.com/Leonxlnx/taste-skill/blob/main/skills/minimalist-skill/SKILL.md)，结合 Product Design 的连续路径原则。Taste 当前主版明确不面向 Dashboard，不能把其营销首屏规范直接搬进产品；本项目采用适合工作台的字体层级、内容节奏与组件取舍。

上版问题：四块矩形区域视觉权重接近、正文和标题缺少对比、工作仅剩摘要行，简单被误做成了机械。此次按上述诊断改变首页构图，保留已有核心功能。实际稿需验证：一眼能找到对话和三窗口入口、看懂重点工作的成果、辨认待决事项，且各区不再重复同一种盒子。不能仅凭使用 Skill 或生成器宣称审美通过。

不采用装饰性营销 Hero、永久循环动效或为视觉而新增的功能。这里只记录项目采用的设计判断，不全局安装或修改 Skill。

## 首页雷达的权重

在已认可的亮色布局内增加雷达的宽度、位置优先级与内容密度。以一条重点观察和两条较短解读作为当前视觉样例，采用标题、可读摘要、材料范围及有依据的工作关联；条数随真实内容收简，不是固定配额。重点与次要条目采用不同字号和段落长度，不新增等大卡片网格。内部团队贡献和外部观察保持各自语义。待决事项仍清楚可达，底部聊天与三窗口入口不能遮住扩充的内容。

## 全页面一致性

普通页面使用同一个 76px 汉堡导航与单一 y 标志，标签统一为首页、雷达、项目、资产、定时任务、设置；当前项选中。沉浸工作页收起全局导航，保留退出、工作归属、布局、团队与流程。示例标识轻量但清楚，工程编号、引擎版本和无依据统计不进入产品界面。

雷达列表和详情用编辑阅读结构；项目列表与两类详情围绕目标和交付；成果页重正文与准确版本；资料与资产用检索/预览和出处；定时任务用委托与运行记录；设置用分组表单。页面有不同密度和结构，共用文字尺度、色彩、边界和主次操作，不把首页布局复制到每页。

跨页设计样例统一为创作实验室、轻记和脚本修订：首页/项目为发送前 v3，过程/结果为本轮修订后 v4；准确正文见 INTERACTION。脚本保留第二步原文依据待补，不编造认知实验、提升比例或已验证的科学结论。成员核查与修订关系是示例情境，不冒充真实运行。
