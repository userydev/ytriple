# 界面与页面规范

本文只维护当前页面职责、视觉与布局规则；对象、动作与输入状态以 [交互契约](INTERACTION.md) 为准，产品目标见 [PRODUCT.md](PRODUCT.md)，实际完成度见 [PLAN.md](PLAN.md)。设计要求不代表实现或用户验收通过。

## 全局导航与信息层级

- 默认展开侧栏：汉堡按钮 + `YTRIPLE` 为唯一品牌入口；折叠后仅保留按钮和导航图标。展开宽 184px，折叠宽 60px。页面标题使用当前页面名，不重复品牌、服务状态或空间名。
- 导航为首页、雷达、项目、资产、定时任务、设置。沉浸工作区收起全局导航，保留返回、工作归属、布局与必要协作操作。
- 亮色、中性表面、明确主动作；页面标题不加装饰英文眉题。内容摘要渲染 Markdown，完整成果和解读保持正文阅读。
- 首页与项目概览使用底部单行轻入口，聚焦或已有草稿/材料时展开；雷达在阅读情境栏准备研究或规划，不在底部重复输入，也不覆盖正文。已有工作沿用原工作输入。
- 主应用/Dock 图标使用 `assets/app-icon.svg` 的绿色三竖条。树枝 Y 仅用于系统菜单栏，提供打开与退出；关闭窗口即退出的规则不因此改变。
- 首页协作节点呈现真实记录顺序和状态，可定位成员记录；不虚构依赖图、成员数量或完成百分比。过程先显示概览和任务，长篇公开分析按需展开且保留原文。

## 视觉尺度

- 首页版式变化程度约 6/10；动效强度约 2/10。功能简单不意味着同样大小的盒子、弱标题或大片无效留白，视觉节奏由实际工作内容决定。
- 首页信息密度约 5/10；沉浸工作约 6/10，空间用来读实质内容。
- 页面底色中性浅灰 `#F8F9FB`，侧栏 `#F3F4F6`，正文表面 `#FFFFFF`；采用亮色，不使用暗色大面积工作面。
- 正文深灰 `#20242C`，辅助文字 `#626974`，分隔线 `#E5E7EB`。
- 单一蓝色 `#4268C6` 限于主要操作、链接和必要焦点，不给正文、普通标题和提示统一染蓝。选中优先用中性浅底与字重，层级先由文字、间距和真实内容建立。
- 正文和界面采用 Geist 与苹方/Noto Sans SC 回退，正文 15–16px、辅助 13px、首页主标题约 30px、重点工作标题约 24px、区块标题约 18–20px。用中等和半粗字重拉开层级，软件界面不用衬线字体和装饰性等宽元数据。
- 留白基于 8px 节奏，主要页面间距 24–32px；对话框内边距约 20px，圆角 10–12px，其余控件 6–8px。优先对齐、分隔和留白，减少盒中盒。

## 边界与控件

**用户明确禁止左侧亮色竖条这一视觉样式，适用于所有 UI 设计。** 导航选中、列表选中、引用、提示、警告、修订段落及活动卡片均不得使用；细左线、伪元素、渐变或阴影模拟的竖条同样禁止。也不能旋转成另一侧亮条或换颜色来变相沿用。此规则优先于早期稿和外部 UI 模板，旧稿中的相同样式不再作为可复用参考。

普通内容区默认无框、无阴影、透明背景，以标题、对齐和留白分组。文章、项目概览、成员贡献、流程步骤、设置分组不使用外层卡片再套内部卡片；不能把去掉的边框逐个换成浅色矩形。列表只在需要辨认行关系时使用极浅水平线，不给每行完整描边。

边界只承担操作或空间语义：输入与选择控件、上传落点、键盘焦点、模态对话框、成果文档表面，以及决策/过程/结果工作面之间的中性细分隔。工作面内部的消息、引用说明和贡献记录保持扁平。选中资料用中性浅底与字重，需要时附勾选或明确状态文字；普通提醒直接在相关内容旁说明，不使用左线或整块彩色提示卡。键盘焦点保留完整清晰的轮廓，不能因去装饰而丢失。

修订标记是版本信息，不是选中态。默认结果正文保持连续排版，可在段落旁用小号但可读的“已修改”文字；依据缺口在相关句子之后作普通文字注记。“比较版本”才显示明确的增删差异。禁止亮条、淡蓝/紫底、大圆角、闪光图标、蓝色小标题叠加成 AI 提示卡。普通正文不因 AI 生成而需要专门的装饰容器。成果修改入口统一为“让 AI 重新整理”（有选段时说明选段），回到原决策输入；不再增加正文编辑器、编辑草稿工具栏或手工合并弹层。

保留底部聊天入口的单一干净表面，其常用操作使用图标；页面其他次级操作按语义采用文字或轻按钮。验收时先看是否能凭文字主次和间距读懂分组，再检查输入、选中和工作面区别是否明确；不以边框数量代替信息层级。

## 状态与动效

静态内容不循环闪烁或逐字播放。过渡只服务聚焦、切换与反馈，约 120–180ms，遵循减少动态效果偏好。新内容只提示，不抢焦点、布局或阅读位置。

点击目标约 44px，键盘焦点清楚。加载占位与实际内容尺寸接近；错误在所属对象旁显示并保留输入；空状态提供可执行入口，无需装饰插图。

状态用真实文字说明，不造完整度、置信度、在线人数或后台已保存声明。可用的能力和设计样例明确区分。

## 先决定对象，再决定页面

页面只回答当前用户的一个主要问题。跨页靠同一工作、成果版本与引用连接；不靠在每页复制聊天框、待办和成果卡来“打通”。对象创建、动作副作用和状态转换以交互契约为准，本文不另定义第二套规则。

| 层次 | 包含什么 | 展开条件 |
| --- | --- | --- |
| 全局入口 | 首页、雷达、项目、资产；定时任务直接可达，设置辅助 | 用户选择工作领域 |
| 对象页 | 解读、项目、成果、资产、委托 | 阅读或管理一个明确对象 |
| 具体工作 | 同一工作的轻对话、双区协作、三面自由排列 | 发送目标或继续已有工作；切视图不运行 |
| 局部配置 | 来源管理、团队搭配、流程、引用选择、版本历史 | 用户正在处理相关对象；不与主要内容并列铺开 |

雷达保持独立阅读逻辑，项目保持持续目标与交付逻辑。不能为了减少页面把两者都塞进聊天，也不能把一次局部配置升级成新的业务领域。

## 首页：决定从哪里进入

首页保留亮色、左侧汉堡导航与底部轻输入入口。主要内容是“继续工作”和有实质内容的“雷达观察”，雷达权重不降低。丰富度来自内容，不来自额外状态模块。

- **继续工作**按工作组织：名称、项目/交付归属、一句实质变化、准确成果入口。用户固定优先，其次本人最近使用；不凭模型猜测重新排序。
- **需要决定**附在对应工作行里。若必须先处理某个待决，“查看待决”替代该行的主行动，而非另外再放“继续”“处理”“进入三窗口”三个同级按钮。其他动作在进入后可达。
- **雷达观察**用一条重点解读和若干短解读承接直接阅读，标题、正文摘要、来源覆盖及与工作有关的具体原因；点击进入同一解读。没有依据不硬凑项目关联。
- **底部输入**默认明确写“新工作”，发送开始新目标；直接可见的工作区图标用于展开同一草稿。它不能悄悄续上当前高亮工作。点击继续后才进入标有工作名称的轻对话。
- 首页查找可到达全部工作，包括未归入项目的工作。

移除独立的“团队最近做了什么”、最近成果、一般待补材料及健康面板。这些内容在原工作可见，首页只显示足以决定下一步的变化。成果片段可作为重点工作的一部分，但不在旁边另复制同一脚本卡。打开轻对话后只保留当前工作输入，退出恢复首页的新工作入口。

## 雷达：先读新闻，再决定是否开展工作

雷达默认是单一新闻流：横向轻范围（全部、关注、具体话题、收藏）加居中列表或正文，不常驻话题管理左栏或研究右栏。列表宽约 880–960px，标题 20–22px、真实导语 15–16px；正文宽约 720–760px，标题 28–32px、正文 17–18px。可用宽度达到 1120px 且用户提问时，才并排正文与约 360–400px 研究栏；更窄时研究是带「返回正文」的全宽页。蓝色只作当前范围的单点强调。

全部是实际收录的公共源与个人订阅新闻池；关注是活动订阅命中的并集，无结果时给「看看全部新闻」，不混入其他范围。无订阅首次进全部，有订阅首次进关注，有效阅读会话优先恢复准确版本、列表位置和队列。上一篇/下一篇沿打开时的队列。卡片用标题和真实导语，来源不足就标明节选或仅标题，不编造摘要。

关注话题是 380–440px 弹层，不挤开正文。建议标签直接保存且不调用模型；自由输入须显式选择「只匹配这段文字」或「让 AI 完善范围」，点后者即提交一次规划。规划区域只给进度、范围和本地命中样例及确认操作，不嵌入通用聊天。新增关注不继承当前话题的编辑身份。成功后关闭弹层、留在原阅读位置。阅读时用返回/收藏/问 AI 的紧凑工具行，筛选回到列表再选。文末仅在确有证据时给出相关、出处或已有解读。

## 项目：交付组织工作

### 项目列表

每项呈现持续目标、当前交付和必要状态，主动作是打开概览。新建/导入是列表工具，不在每个项目再复制一组聊天入口。新建先名称、类型、目标，导入再选择范围；不能把目录存在叫作已理解。

### 项目概览

项目页回答“正在交付什么，下一步推进哪里”。目标与已采纳标准以短摘要呈现，详细标准、正式资料和反馈在局部入口中。

当前交付是主要阅读单位：交付目标、采用版本或暂无采用版本、最近实质变化、相关工作。选择明确的工作后显示“继续：工作名称”的输入与展开入口。多个工作无法确定时先显示工作选择，不根据最新消息自动替用户选定。

“开始另一项工作”是明确的次级动作，会把输入标为新工作并保存原草稿。项目对话不作为与交付工作平行的万能线程。没有交付时允许先围绕目标开展工作，之后再关联交付，不强迫先做管理配置。

| 语义 | 媒体项目 | 软件项目 |
| --- | --- | --- |
| 长期目标 | 频道、受众与已采纳表达标准 | 产品目标与已确认边界 |
| 交付对象 | 一条作品；可能含脚本和制作说明 | 一个版本或明确交接目标 |
| 当前工作 | 选题、脚本修订、反馈复盘等真实目标 | 需求讨论、范围取舍、交接检查等真实目标 |
| 使用证据 | 实际发布或导入反馈 | 实际交接、外部开发或回验记录 |

不新增永远占满首屏的表达标准、项目材料、团队活动与下一步卡片；它们出现在相关交付或按需打开。运行成功不自动改变交付完成状态。

### 资料与成果

资料列表区分原始材料、正式资料、引用与草稿，选择后预览准确内容和覆盖。选择/浏览不触发扫描或上传；所选资料只有加入工作输入才成为本轮候选上下文。

成果详情是同一个成果阅读器，可从项目、工作、资产打开。默认显示入口指定的版本，清楚标示是否有更新版本；不按最新版本强行覆盖项目采用版本。正文是主角，历史、依据和导出为局部工具。选段修改回到原工作并携带版本，不另建“成果聊天”。

## 工作：判断、过程和成果相互解释

轻对话承接快速目标、团队答复与下一次输入。进入沉浸后默认左决策、右过程/结果页签；三个面可自由排列。工作标题与返回位置始终明确，布局与团队配置分开。

- **决策面**：可折叠的当前目标、团队的可读结论、用户交流与确实需要的选择。一般材料缺口不自动变成待决。这里不重复整份成果与所有成员分析。
- **过程面**：按真实问题呈现负责人、材料、公开分析、分歧及修订结果。每个结论可定位来源或成果段落。成员视图/轮次筛选按需打开，不用四个固定步骤填满画面。
- **结果面**：完整成果及当前版本，必要的待核标记；整版/选段交给 AI 整理、比较、导出。版本历史和采用关系按需展开，不常驻完整管理面板。

例如研究员读到摘要、核查员质疑依据、编辑员保留限定措辞，应该形成一条可理解的因果关系。决策面交代处理结论，过程展示原因，结果显示改动后的段落；不能在三个面复写同一条警告。

首次进入时有成果可优先打开结果，没有成果可打开过程；明确“查看过程/结果”的入口尊重点击意图；随后始终恢复用户自己选的页签。运行中只提示新内容，不强制切换。总结过程/复盘仍可直接操作，但属于过程工具，生成内容回到同一结果面。

团队与流程是工作中的次级配置：搭配和流程分别版本化，当前运行快照不变，下一轮生效。初次发送不要求选角色、人数、模型或节点图。停止针对当轮执行，离开、收起或重排只改变视图。

工作台变更回执出现在决策面靠近对应对话的位置。回执用名称说明改了什么，并显示来源、关键词、下次时间、时区、周期、调用上限和“桌面需保持运行”等后果；内部 ID 不作为主文案。等待确认、已应用、已撤销、失败和过期各自可辨，失败不移除卡片，成功可跳到实际对象。

## 资产：把已有积累带回工作

自动保存的工作历史可查找，但资产首页优先呈现用户主动收集的材料、成果与方法。加入资产保存引用与用途，不拷贝第二份成果；“沉淀为方法”才是明确的新产出。

列表主动作是打开了解；详情主动作是“用于工作”。先选择已有工作或新工作，把准确版本和范围加入草稿，发送才调用团队。方法的适用条件与验证状态是内容，不作为每行一排状态徽章。仅收藏不表示已验证、已启用或获准执行工具。

## 定时任务：一次工作变成持续委托

页面主动作是“添加定时任务”，进入现有工作区说明目标和时间；已有任务提供“跟团队调整”。列表与阅读状态保持主内容，高级设置才打开完整表单。对话始终显示绑定任务及 revision，避免返回页面或切换对象后静默改到另一任务。

保持左侧直接入口，列表表达做什么、触发和最近实际结果，主动作是查看委托。新建与“将这项工作设为定时任务”使用同一表单；从工作进入时继承目标、资料、团队与结果归属，用户重点决定触发及必要限制。

每个委托绑定一项工作，每次运行和成果版本归回它。运行记录是委托详情的一部分，查看结果打开准确版本。暂停后续触发与停止当次分开；没有新信息显示检查结果，不凑一份报告。需要本地资料但执行位置不可达时说明缺口，不假装远端能读。

## 设置：配置使用条件

设置默认进入账号，分类为账号、AI 模型、本地目录、空间与备份、团队与流程、关于应用。使用标题/一句用途、当前值、状态、文字操作的行结构；版本/设备/构建归关于应用，空间名称归空间管理，服务连接归账号。高级选项按需展开，自带 API 配置使用独立弹窗，退出账号需要确认。来源、项目设置、资产恢复等管理操作保留可读文字。只有当前动作受影响时，就地提示缺项并提供定向设置入口；从设置返回原草稿，不要求重新输入。设置项没有接入实现时不得展示成功、已同步或全自动保存等承诺。

## 操作统一规则与异常路径

| 情况 | 行为 |
| --- | --- |
| 无内容 | 展示当前领域的真实开始入口；不造示例记录作为用户内容 |
| 未发送展开/退出 | 同一草稿；没有永久空工作或模型调用 |
| 重复发送 | 同一提交身份，防止重复工作和重复付费；界面保留可恢复状态 |
| 运行中补充意见 | 明确提交才进入下一轮待发；停止/失败/待决暂停自动续发，可编辑撤回，不并发覆盖 |
| 模型不可用 | 保留草稿和历史阅读，连接后回原目标 |
| 缺原文 | 就地标明覆盖和对结论的限制；能继续的部分继续 |
| 过时待决 | 告知目标/版本已变，原回答不静默应用到新范围 |
| 生成期间出现新版本 | 保留当前版本和生成候选，准确引用后交给 AI 整理；不提供手工合并，不能覆盖 |
| 窄窗口 | 收起导航，按需切完整工作面；输入不遮正文，拖动有菜单替代 |

## 三个工作面，多种排列

决策、过程、结果是内容与操作的职责划分。默认布局采用左侧决策、右侧过程/结果切换；用户可以把三个工作面展开，调整位置、横向或纵向排列、大小与组合，也可以重新合并。自由排列发生在应用工作区内，不要求创建三个操作系统窗口。

双区布局下，决策面负责持续交流、目标与用户判断；右侧通过同级入口完整访问过程和结果。过程包含实质公开分析、委派与证据，结果包含完整正文、版本比较与 AI 重新整理入口；两者不因共享显示区域而变成简短预览。

布局只改变展示。隐藏过程不停止 Agent，展开结果不启动生成，移动工作面不另建会话。成果或过程更新只提示有新内容，不自动切换当前页签、抢焦点或改排列。用户主动点击“查看结果”等明确导航动作时，才切到相应工作面并定位对象。

## 连续性与状态归属

- 工作、运行、过程记录和成果版本由产品运行时维护；界面不是这些对象的唯一持有者。
- 每个工作面保留自己的阅读位置、筛选、选择和对话草稿；页签切换、重排、聚焦与还原不会重置它们。
- 选中一条过程记录追问或一段成果要求修订时，决策面携带准确对象、版本与范围。移动区域不改变引用。
- 默认布局偏好按设备保存，工作内的阅读与对话输入状态按工作保存。设备之间接续同一工作时，不强制把大屏排列复制到手机。
- 提供恢复默认布局与聚焦/还原操作；恢复布局不清空输入、运行或成果。小空间仍能直接切换三个完整工作面。
