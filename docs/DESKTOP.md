# 桌面工作体验

统一确认入口：[UI 与交互确认稿 v1](UI-BASELINE.md)。本文保留对应领域的详细规则。

依据：[PRODUCT.md](PRODUCT.md)。整理日期：2026-09-16。本文定义交互要求，尚不代表界面已实现。

## 产品页面与具体工作

正常启动进入首页。首页、雷达、项目、资产和定时任务各有自己的页面逻辑，不能把三工作面当作整个产品的通用页面模板。页面职责、对象关系、导航与状态规范见 [页面设计](PAGES.md)。

三工作面在用户展开沉浸工作时出现，是主要协作界面；项目概览负责持续目标、交付和依据，雷达负责阅读与消化。工作可以属于一个项目并关联其中一个交付，也可以独立存在；雷达议题通过引用关联。对象与命令遵循 [INTERACTION.md](INTERACTION.md)。

从项目进入工作时保留项目与工作两级身份，并能返回原来的项目页签、筛选和位置。从雷达进入工作时保留议题与引用版本。切换全局页面不终止运行、不清空草稿；回到同一工作继续原状态。

## 轻对话到沉浸协作

首页输入明确为新工作；雷达正文后提供开展工作入口，点击才展开携带准确解读版本的输入；项目选中交付后明确接续其已有工作，另开目标需切换为新工作。一个页面状态只保留一个编辑中的输入上下文。轻对话打开后不再并列一个含糊的全局输入，切换时保存旧草稿并更新工作名称。

发送后先在当前上下文中承接回复与继续输入，显示正在继续的工作身份和直接可见的工作区展开图标，悬停/聚焦说明含义。底部入口的材料、交流对象、发送/排队/停止、快捷键和状态统一见 [COMPOSER.md](COMPOSER.md)。轻对话不是另一个单 Agent 产品，三窗口也不是另开任务或升级模型套餐；两者使用同一团队、工作 ID、消息、运行、草稿和成果。

进入沉浸模式收起全局侧栏与无关页面内容，保留工作身份、返回入口、必要协作操作和三个工作面。退出回到原页面的轻对话与阅读位置，运行不停止，草稿不丢失。尚未发送时展开只转移草稿，首次发送才建立工作及运行；已存在工作展开不得重新提交。

团队特色由可读的实质协作呈现：谁提出问题、谁核查什么、有哪些证据和限制、讨论怎样改变成果。过程与结果切换明显，重要过程变化可以提示查看，但不强制跳转。不用成员头像数量、空关系图或流水日志代替团队可视化。

过程按真实问题串联证据、异议和修订，成员是贡献者而非固定栏目。材料缺口就地标注；只有必须由用户作出的取舍才进入决策面并由首页引用。首次进入有成果可展示结果、无成果展示过程；明确入口和用户已有页签选择优先，后续输出不能抢页签。选择成果打开其准确版本，项目采用版本与更新草稿分开。

## 三个工作面，多种排列

决策、过程、结果是内容与操作的职责划分。默认布局采用左侧决策、右侧过程/结果切换；用户可以把三个工作面展开，调整位置、横向或纵向排列、大小与组合，也可以重新合并。自由排列发生在应用工作区内，不要求创建三个操作系统窗口。

双区布局下，决策面负责持续交流、目标与用户判断；右侧通过同级入口完整访问过程和结果。过程包含实质公开分析、委派与证据，结果包含完整正文、版本比较与 AI 重新整理入口；两者不因共享显示区域而变成简短预览。

布局只改变展示。隐藏过程不停止 Agent，展开结果不启动生成，移动工作面不另建会话。成果或过程更新只提示有新内容，不自动切换当前页签、抢焦点或改排列。用户主动点击“查看结果”等明确导航动作时，才切到相应工作面并定位对象。

## 连续性与状态归属

- 工作、运行、过程记录和成果版本由产品运行时维护；界面不是这些对象的唯一持有者。
- 每个工作面保留自己的阅读位置、筛选、选择和对话草稿；页签切换、重排、聚焦与还原不会重置它们。
- 选中一条过程记录追问或一段成果要求修订时，决策面携带准确对象、版本与范围。移动区域不改变引用。
- 默认布局偏好按设备保存，工作内的阅读与对话输入状态按工作保存。设备之间接续同一工作时，不强制把大屏排列复制到手机。
- 提供恢复默认布局与聚焦/还原操作；恢复布局不清空输入、运行或成果。小空间仍能直接切换三个完整工作面。

## 团队独立于工作区

团队搭配决定成员与责任，流程决定怎样协作；两者独立配置、分别版本化。成员数量、模型类型和流程步骤不映射成固定窗口数量。过程面根据真实记录呈现成员与协作关系，不以某个固定团队模板编写页面。

切换团队搭配、更新流程或 Skill 时说明生效范围。旧记录继续使用当时的成员身份、责任和版本；当前执行不因新版本发布而悄悄换规则。具体运行边界见 [架构方向](ARCHITECTURE.md)。

## 操作验收

用一项真实工作，先在双区布局中交流、读分析、改成果；展开三面并交换位置、调整比例，再合并为页签。期间收到新内容，切换其他工作后返回，最后关闭重开。

先从首页、雷达解读或项目轻对话发出目标，再展开/退出沉浸视图；另测尚未发送的草稿直接展开。两种入口都只在明确发送时调用一次模型，进入三窗口不创建重复工作，不隐式读取整个项目，也不丢失页面位置或已引用材料。

应观察到：同一工作和准确版本贯穿全过程，过程与结果均完整可用，草稿与位置保留，没有重复提交模型调用或停止成员。用户正在阅读旧版时，新版仅提示可查看。

再分别更换成员搭配、升级协作流程。新运行采用所选版本，历史记录保持原貌，原成果继续可引用；界面布局和 ycore 调用协议无需随之改写。此验收检验独立升级能力，不要求当前建设插件市场或流程编辑器。

设置 → 备份与空间可将当前本地数据库导出为 `.ytriple-backup`，再经内容预览恢复到独立空间。原空间不被覆盖，切换通过重启完成。备份保留已读内容和关系，不包含 AI/Code 原始文件或服务凭据；恢复空间的自动任务保持暂停。当前单文件上限为 64 MiB，超限明确失败。

设置页的“AI 模型”与“信息服务 · ycore”分别配置。自带 API 可独立完成团队工作与 AI 修订；ycore 继续提供材料和订阅读取。模型连接测试只发送固定短句、不附带工作材料，点击测试会产生一次请求，保存本身不测试。历史过程显示当轮模型和接口，切换供应商前需要处理尚未结束的工作与雷达整理。

直连断线后提供“核对本地记录”；如果没有完整成功记录，保留部分内容和未知状态。用户明确“结束本地等待”才释放本地阻塞，界面必须说明这不代表远端已取消、没有用量或允许自动重发。成果仍通过 AI 修订保留新版本，不提供手工结果编辑器。

团队与流程 → 成员可用工具可为成员选择材料查阅和数值计算，保存搭配新版本并应用后作用于后续运行。过程在实际请求旁显示工具用途与执行状态，展开后先呈现原文片段、准确材料入口或计算值；原始输入、返回和时间留在二级展开。工具结果与成员公开分析分开，可以针对原记录追问或纳入复盘，不把工具成功视为内容或项目目标已验证。
