# 界面与交互验收

2026-09-13。本文把产品定义 5.2、7.1 的交互要求落实到当前界面与验证，不另建产品范围。

**最新结果：本轮界面仍被用户否定，当前停止叠改。本文列出的能力与动作不能被当作现有面板排布已经合理的证据。**

## 这次为什么反复改偏

此前用“看起来简单”和“按钮能点”代替了有效工作：隐藏分析只剩日志，隐藏项目状态只剩对象列表，减少面板变成减少并行能力。文档虽保留同窗口关系，却未把同时对照、修正复盘和状态依据写成可验收行为；工程记录又把偏差固化成规则。

本轮又犯了同一类错误：虽然补回能力，却把更多信息装入既有面板，没有先证明用户能识别当前重点、理解状态并自然完成下一步。将视觉与整体交互检查放在实现之后，导致用户再次承担发现根本问题的成本。

后续先从既有需求提炼主要工作路径，用可操作界面检查信息主次、状态、下一步与多窗口协作，再展开工程实现。若反馈继续否定方向，应立即说明路线未成立、停止扩建，而不是继续换排版、补功能或追加测试。页面数量、面板数量、Skill 名称和测试数量均不能代替这一判断。

## 设计约束

使用官方 [Taste skill](https://github.com/Leonxlnx/taste-skill/blob/main/skills/taste-skill/SKILL.md) 的适用部分。本地审查副本在 `.ytriple/design-reference/taste/SKILL.md`。当前新版明确不覆盖复杂产品工作流，因此只采用排版、对比度、间距、空错反馈和改版保留能力的原则。

当前界面面向个人开发者和创作者的长时间桌面工作：低装饰、低动效、内容可对照。采用现有系统中文字体和单一绿色操作强调，正文使用中性色；标题用字重建立重点。协作表面使用分隔与留白，不能重复套外框、栏目标题和筛选标签。已有键盘、焦点、草稿保护不得退化。

## 必须走通的路径

| 路径 | 用户应看到什么 | 验收动作 |
| --- | --- | --- |
| 启动 | 工作台与当前需要关注的事 | 保留最近工作后重开，仍进入首页且不运行 |
| 进入软件项目 | 可比较的目标、阻塞、下一工作和变化依据 | 选择项目直接进入全尺寸工作区；无任务时不产生空任务 |
| 理解已有项目 | 正式资料与目录观察分开 | 从状态发起理解，实际读取可用正文加入工作；读不到明确失败/未知 |
| 开始/接续协作 | 交流、成员分析与成果在同一上下文 | 从已有工作切到新工作再返回；不丢草稿、不串项目 |
| 对照与干预 | 当前判断、关键修正、不同成员贡献 | 同时看过程与文档；展开出处与准确版本；直接向成员追问 |
| 调整空间 | 两面/三面和独立聚焦 | 拖两条分隔线、键盘调整、双击恢复比例；聚焦后恢复/切工作不困在旧面 |
| 复盘 | 可核查做法、问题、修正和未验证点 | 总结当前筛选范围并保存；失败就地重试；从总结回到依据 |
| 修订成果 | 同一份内容与版本 | 编辑后切页再回来草稿保留，保存再重开有新版本；旧引用不指向新正文 |
| 切换与慢操作 | 明确归属与就地反馈 | 创建/导入未返回时切页；迟到结果不抢页面、不关闭新输入、不串任务 |
| 媒体工作 | 频道、作品和所用准确版本 | 从阶段准备进入共享工作区；继续旧任务后状态跟随实际工作 |
| 窄窗口 | 同一工作内容的可达入口 | 交流、分析、项目/成果同级切换；没有横向页面溢出或隐藏焦点 |

## 证据与限制

数据投影测试验证状态与依据；交互测试验证操作结果和异步归属；隔离 Electron 验证实际阅读、切换、编辑、尺寸与滚动。合成资料必须保持合成标识。模型替身证明协议，不证明真实模型质量；真实调用与用户体验分别记录。

每次发现偏差先改本来错误的语义或交互，再改表现。对源文档的修订必须来自用户目标和实际发现，不能为通过已有测试降低要求。
