# ytriple 后续开发计划

更新：2026-09-17。用户接受当前 UI 作为阶段基线，要求提交版本；下一阶段改为 **ycore 基础服务优先，ytriple 只做必要配合**。本轮仅提交与规划，不启动功能实施。本文件替代旧 A1/A2/A3、B/C 排期；完整产品方向仍见 PRODUCT。

## 当前基线与目标

- ytriple 产品代码基线 `0a6ab53`，包含此前 UI 收口提交；安装构建 `fb9aeb861f3b12ce`，本机开发签名。当前 UI 获准作为阶段版本，不等于完整产品、公开分发或远端能力已验收。
- ycore 源码基线 `68e54f1`；最近一次已验证的服务发布是 `dev-20260917-0f85bcb`。本轮只核对仓库和交付记录，没有重新检查线上健康或重新部署。
- 已有桌面材料→团队→AI 修订→成果/资产/项目采用的真实公网验证，但使用受保护联测凭据；正式个人账号日常连接仍未完成验收。
- ycore 已有身份/权益、材料版本与增量、feed 读取、流式/后台 AI、按键找回、用量控制和后台授权。存在接口不代表客户端完整可用，不重复重建这些能力。
- ytriple 私有服务已有部分空间、持久宿主和租约代码，完整远端控制与桌面服务空间尚未接通，未部署。

下一阶段只交付一个结果：现有 ytriple 能稳定消费 ycore 的身份、信息和 AI 服务；获准的后台工作能继续并可靠取回，数据、权限、失败与用量有据可查。基础服务完成后，再逐项改善 ytriple 的产品能力。

## 分工与冻结范围

| 归属 | 本阶段责任 |
| --- | --- |
| ycore | 稳定公共 API、身份与产品权益、共享信息采集/来源/修订/增量、模型适配、持久 AI 任务与授权、用量与服务运行保障 |
| ytriple | 消费 API 与账号会话、材料落盘与引用、执行状态展示；复用现有团队内核补齐必要的私有服务控制、获准上下文和成果接续 |
| 保持本地 | AI/Code 根目录、原项目文件、未获准上传的材料与凭据；服务器不能读取本机路径时明确说明 |

ycore 优先不等于把团队编排、雷达判断、项目资料和私有成果搬进公共信息库。服务部署位置与代码归属分开；复用既有 VPS 和托管数据库，不新增平行网关或通用平台。两仓库通过版本化 API 配合，不直接读写对方业务表。

冻结首页、雷达、项目、资产、定时任务和三个工作面的功能范围。仅修复接入所必需的入口、状态、错误与恢复反馈；不继续整套 UI 重画，不加手动成果编辑器、移动端、付费套餐、更多模型、通用 MCP/插件平台、复杂知识图谱或批量连接器。团队搭配和流程保持独立版本。

## 五个顺序工作包

每包都包含 ycore 实现/修复与 ytriple 最小消费验收，不能先将所有后端模块写完再一起联调。只在上包出口通过后进入下包；运行保障从第一包开始积累，在 F5 集中验收。

| 顺序 | 用户可获得的结果 | ycore 重点 | ytriple 必要配合 | 阶段出口 |
| --- | --- | --- | --- | --- |
| F1 身份与日常连接 | 安装版通过现有设置使用本人获准服务 | 验证已有托管身份发现、身份/权益、失效与禁用语义，修复真实阻塞；首版手工授予必要权益即可 | 现有登录、系统安全存储、刷新/退出、重开恢复；正确区分开发凭据、自带 API 与个人账号 | 正式域名＋真实个人账号＋实际安装版正向通过，不靠脚本注入；无权限、过期、切换账号不串数据；记录明确缺失的外部配置 |
| F2 AI 调用与恢复 | 团队调用可追踪，断线/重启不会重复付费 | 固化已有 SSE、持久任务、查询/按键找回、幂等、用量/并发与后台授权契约；明确取消与未知状态的实际能力 | 复用现有适配器，模型调用关联原工作/成员；断线后先查询，结果持久化后才展示完成 | 流式与后台任务各走通；首事件丢失、服务重启、重复提交、授权撤销/额度不足有证据；无法确认远端取消时不显示“已取消且无费用” |
| F3 信息与雷达输入 | 雷达稳定获得有出处、有覆盖范围的真实材料 | 补齐 M0 第二条独立真实采集路径；核查调度、去重、修订、来源状态、快照/增量与恢复游标；受阻上游有界替换 | 沿现有雷达消费材料；保留引用版本、已读/收藏和议题归属；失败不清空旧材料 | 两条独立真实路径通过，非仅增加另一个同类 feed；至少两个实际调度周期；正文变更、重复获取、失效游标不丢失或伪造资料；不冒称读过全文 |
| F4 最小后台接续 | 关闭桌面后，一项获准工作可完成并回到原位置 | 验证已部署执行授权、撤销、运行隔离和用量边界，提供共享 AI/信息能力 | 补齐现有私有服务的提交/查询/答复/停止与授权持久化，接通一个服务空间；先一项普通工作，再复用同一路径接一项既有定时委托 | 退出桌面→服务继续→重开取回原过程/版本；重复命令不重复调用；等待答复、取消竞态、撤销和本机资料不可达明确可见；实际部署并联测后才算通过 |
| F5 基础服务交付 | 可以持续使用、发现故障并恢复 | 补足健康与任务失败/积压/容量告警、日志限额、数据保留、备份计划及恢复演练；核对运行与迁移权限、版本和回退 | 同一安装候选验收升级、断网重连、服务不可用、重开与原资产/项目采用关系；修复本阶段回归 | 同一桌面构建＋兼容服务发布完成正式路径；至少 24 小时观察且覆盖两个真实调度周期、一次故障恢复和一次独立备份恢复；记录恢复耗时与保留边界，不宣称单机高可用 |

F4 是现有服务模式的最小贯通，不建设通用多设备同步、文件云盘或新的调度平台。若它需要超出既有运行内核的大改，先给出具体缺口与缩小方案，不能借“基础”无界扩展。

## 首个工作包怎样开始

下次实施从 F1 开始：确认正式账号与必要权益的现状，沿安装版现有设置走一遍连接→读取材料→一次最小 AI 调用→退出重开。先利用已有配置和证据；需要个人登录操作或缺少凭据时列明具体阻塞，不生成假账号、不把测试身份当本人账号。只修复这条路径暴露的必要问题，形成一组可复现结果后封包。

不先做新账号中心、OAuth/MFA 或订阅支付。开发联测凭据可继续用于隔离测试，但不能替代 F1 的日常使用出口。

## 进度、验收与停止规则

- 当前剩余量是上面五个有限工作包，不是“五个模块从零开发”；F1–F3 主要核查、修复与接入，F4 是最大工程缺口，F5 含必须等待的运行观察。尚未据此给出天数或完成百分比。
- 同时只推进一个主要包。每包开始前列有限缺口、改动位置和完成条件；结束即提交、按需发布、记录证据，不长期累积未提交实现。
- 完成必须区分：代码、自动检查、真实账号/来源/模型路径、安装/部署。替身测试不替代真实验收；已有证据未受变更影响则复用，不反复付费跑全流程。
- 交付记录包含两个源码提交、桌面 buildId、服务镜像/迁移、验收路径和回退位置；不改 main，不自动公开发布。
- 发现额外产品需求记录到基础服务之后；只有阻塞本包出口的缺陷才插入。用户要求总结或暂停时立即停止实施。
- F5 通过后停止扩展基础平台，进入 ytriple 的小版本改进：先核心协作与信息理解的实际体验/质量，再按使用反馈选一个功能升级。每轮一条用户路径，不重新把 PRODUCT 全量变成待办。

本轮用户要求的是版本提交和后续规划，不视为自动启动 F1。中央登记中的历史描述漂移仍另行治理，不随计划自动修改中央规则。
