## 1. 本次重排的结论

当前优先按 [INTERACTION.md](INTERACTION.md) 重整关系，再由 PAGES 推导界面。先验证“雷达阅读 → 发送目标 → 同一工作协作 → 局部修订 → 项目采用版本 → 资产复用”与“项目接续 → 答复待决 → 范围修订 → 交接”两条路径。先用关键视图校对对象、动作和返回位置，再做可操作原型与实际服务；不继续批量扩充静态页面。图稿可否定原页面结构，领域规则也须根据实际路径回改，但不能由生成器随意增加功能。

验证门槛：明确工作何时创建、何时复用；导航调用数为零；一个提交只产生一次运行；采用版本不随草稿覆盖；一般缺口不制造待决；页面退出不取消执行。没有交互证据前，阶段状态保持设计中。移除首页独立活动流/重复成果区，项目万能聊天改成明确工作输入，资产入库改成复用引用。团队和流程独立升级、三工作面可排列、雷达阅读权重不变。

**ycore 承担公共信息与 AI 服务，ytriple 集中做好“理解材料、团队协作、形成成果、修订与继续工作”。** 先确定完整产品的页面职责与导航，再按真实路径接通业务能力。首页、雷达、项目不能等核心做完后才补页面逻辑，也不能用空导航和数据面板代替真实协作。页面设计见 [PAGES.md](PAGES.md)。

首条验收路径：用户输入目标并选择真实材料 → 团队围绕不同问题分工与核查 → 三窗口能对照交流、公开分析和成果 → 用户指出一个问题 → 同一成果修订 → 关闭重开后继续 → 导出给人或工具使用。

服务器已存在，消除了重复建设采集、模型代理和基础设施的必要，但没有替代 ytriple 的产品运行时。远程模型调用、服务端团队运行、个人工作空间跨端接续是三种不同交付。

## 3. 两个项目的交付边界

| 能力 | ytriple 负责 | ycore 负责 |
| --- | --- | --- |
| 信息 | 个人订阅偏好、阅读/收藏、议题、相关性、解读与跟进 | 公共来源获取、标准化、去重、材料修订、出处、增量协议 |
| AI | 目标、角色、上下文选择、成员协作、方法、输出质量、成果修订 | 供应商适配、共享模型调用、调用状态、用量与服务限制 |
| 工作与资产 | 项目、作品、工作、过程、成果、反馈、私有资料与权限范围 | 不管理产品工作空间；AI 调用输入/结果按服务策略受保护保存，不进入公共材料池 |
| 定时执行 | 用户委托的含义、触发条件、资料范围、成果归属、提醒 | 公共来源调度和通用后台 AI 调用；不解释栏目或项目目标 |
| 服务模式 | 团队远端运行和私有工作空间接口仍由 ytriple 维护 | 共享身份集成、权益与用量，以及信息/AI 接口 |
| 运维 | 桌面安装、升级、本地恢复；未来产品运行模块 | 公共服务部署、数据库、来源与模型可用性、恢复 |

代码归属不等于新增服务器。将来的 ytriple 产品运行模块可以复用现有 VPS 和托管数据服务，独立权限与数据边界，不为它再采购主机或另搭模型网关。具体部署在需要服务端团队运行时落实。

## 4. 开发阶段与出口

阶段按可使用的结果划分，不按页面数量或固定天数承诺。每阶段先跑一条完整路径，验证通过才扩大能力。相邻阶段可提前准备独立部分，但不能跳过关键出口。

### P0：建立新工程，完成真实服务接入

**目标：在真正的桌面程序里读取一份材料、发起一次 AI 处理，并重开查看已保存结果。**

- 建立桌面壳、类型化本机边界、持久存储与迁移、可复现启动和构建。默认方案为 Electron + React/TypeScript，本机 Node 运行领域逻辑，详见架构文档。
- 按页面规格建立统一导航和独立页面边界；正常启动是首页，项目概览与具体工作分开。各入口保留对象身份、返回位置、筛选和草稿，业务数据未接通时如实呈现空或不可用状态。
- 实现 Y-Core 信息与 AI 适配器：能力检测、真实材料读取、快照分页/增量落盘、修订引用、流式终态、后台 JSON 状态恢复与错误显示。
- 服务凭据由操作者配置并由本机安全存储管理；不进入 renderer 或安装包。没有连接时仍能打开本地材料。
- 在首页输入目标并轻对话，可展开决策/过程/成果沉浸视图完成一条真实链路；进入/退出只改变展示，不创建重复工作或模型调用。尚未完成团队协作时明确为接入验证，不伪装多成员工作。

**出口：** 从干净安装启动；同一真实材料的版本可追溯；两页快照与增量重拉不重复；一次真实 SSE 与 JSON 成功可查；断流不变成功，未知结果不自动重复付费。公网路径可用或明确保留隧道联调限制。此阶段不是产品 Alpha。

### P1：交付可用的团队与三窗口核心

**目标：用户能通过真实分工和多轮纠正，得到比单次回答更可用的成果。**

- 建立工作、运行、成员任务、公开分析、成果版本和决定的共同身份；简单目标可由一个成员处理，复杂目标有真实委派、核查、回信与汇合。
- 默认左侧决策，右侧切换过程/结果；也支持将三面展开自由排列、调整空间、聚焦还原。过程与结果在共享区域中仍完整可用，布局和切换不影响执行。新输出不抢滚动、焦点、页签或布局。
- 三窗口入口清楚可见，轻对话与沉浸共用团队和状态；沉浸收起无关页面内容。以成员的实质贡献、证据异议和成果变化体现协作特色，不能把主要过程能力藏成设置项。
- 可以从过程中的判断追问，从成果段落发起修订；目标变化、成员切换、停止和迟到结果不丢失上下文，也不覆盖新的有效版本。
- 少量内置方法型 Skill 真正参与工作，记录所用版本与范围；缺依赖不冒充执行。团队可调整责任，历史身份保持原快照。
- 将团队搭配、流程定义、执行内核与布局分别实现。搭配和流程独立版本化，每次运行锁定实际快照；升级不改写历史或静默影响执行中的任务。同一流程换一套成员、同一团队升级流程都不需要重写界面或 ycore 模型接口。
- 提供“总结过程”和“复盘工作”：分别依据已记录过程及真实反馈生成成果；证据不足明确保留，不能补造当时的思考。
- 保存、查找、继续、归档独立工作；Markdown 成果由 AI 重新整理形成新版本，可比较版本和导出，当前不做成果文件直接编辑。首页只呈现真实工作和需介入事项。

**出口：** 用实际开发需求材料和实际创作材料分别跑一轮；至少有一次成员异议引发修订、一次用户修改受众/约束、一次针对局部结果追问、一次重启继续。验收查看过程与成果内容，不以头像、状态事件或调用次数证明协作。主要对应 AC-01/03/04/06/11/12/13/16/17/18/20/22。

P1 的完成标准包括实质公开分析、总结/复盘和准确引用；不能将这些延后为“界面优化”。

### P2：把核心放进雷达与两类真实项目，形成个人 Alpha

**目标：用户可以在日常阅读、软件项目与媒体创作之间连续使用已有工作与积累。**

| 路径 | 本阶段最小完整结果 |
| --- | --- |
| 雷达 | ycore 公共材料形成有依据的议题解读，正常阅读无需提问；新证据说明相对旧理解的变化，支持纠正筛选；进入研究时沿用材料身份和版本 |
| 软件项目 | 产品讨论形成真实定义；选择目录和模板后初始化可交接的项目材料；已有项目分批读取源码/配置/测试/文档并明确覆盖，只向约定建议文档持续回写 |
| 媒体项目 | 从频道条件与资料形成选题、脚本和必要制作说明，版本均归同一作品；手动登记发布与导入真实反馈即可复盘，不以平台 API 为前置条件 |
| 资产与复用 | 工作/材料/成果可统一查找引用；明确采纳的项目或频道标准在后续相关工作生效，其他项目不被污染；最小备份与不覆盖冲突的恢复可用 |
| 本地自主使用 | 一条自带 API 路径可独立运行团队；首个直连适配采用 OpenAI 兼容文本调用，能力差异明确；关闭官方服务后本地文件仍可用 |

**出口：** 开发者完成“讨论 → 初始化 → 实际交接版本”，创作者完成“选题 → 脚本/制作说明 → 真实反馈 → 下一次采用修正”。雷达完成一次多材料消化与增量理解；两种项目复用同一团队内核，没有复制聊天/成果系统。主要对应 AC-02/05/07/08/10/21/23/24，以及 P1 连续性回归。

个人 Alpha 只面向受控本人使用：桌面团队在本机编排，AI 默认调用 ycore。它**尚不是 PRODUCT §3.2 中团队在服务器执行的完整服务模式**；退出客户端后不承诺继续运行整项团队工作。

### P3：服务端团队运行、定时委托与外部试用

**目标：已授权的工作能在客户端关闭后继续，并可靠地回到原工作和成果。**

- 将已验证的 ytriple 领域运行时部署为产品模块，团队逻辑仍在 ytriple 仓库维护；提供私有工作、过程和成果接口。不把团队/频道/Lib 塞进 ycore 公共库。
- 在 ycore 接入托管用户身份与服务端权益/用量；产品运行模块验证同一身份并逐请求校验私有对象权限，不能只因来自同一服务器就放行。
- 桌面明确区分本机工作空间与所选服务空间，支持受控导入/导出，不自动全盘上传或切换数据；重连取得原运行，设备草稿和成果并发修订能处理冲突；当前不做成果文件直接编辑或手工合并，修改统一经 AI 重新整理。
- 实现定时任务完整入口：新建或从原工作转为委托，说明做什么、何时、结果到哪里；查看、编辑、暂停、立即运行与停止当次含义清楚。
- 首批远端委托只用公共材料或明确上传的资料，例如跟进一个议题。需要本地文件或登录状态的任务保持本机执行/等待，不伪装远端可达。
- 处理时区、休眠、补做、重复触发、未知执行、暂停与取消；没有新增理解不重复生成。结果和提醒归回同一工作，普通变化可汇总，需行动事项不重复。

**出口：** 关闭桌面仍有一次真实远端团队/定时执行完成；重开定位准确结果；另一受控客户端验证同一服务工作接续；异常、重复触发和权限撤销不丢状态或重复计费。外部试用前完成用户隔离、权益、备份恢复和实际分发包验证。对应 AC-09/14/15/19/25 中桌面及协议部分；手机交付不在本阶段冒充完成。

P3 服务工作空间可先验证，再补定时执行；身份与用户隔离是对外试用的前置条件。无需先接支付。ycore M0 的剩余服务可靠性项目需在依赖它对外提供服务前收口。

2026-09-17 实施状态：桌面账号、ycore 托管身份和权益已接通；`apps/service` 私有空间 API、原子命令结果、执行租约与共享 Runtime 的调用前保存已通过本机隔离测试。当前接口没有公开工作提交，未部署产品运行宿主；后台授权、运行控制路由、远端调度、桌面服务空间与实际客户端关闭后的验收继续按本阶段出口推进，不能将内部模型替身验证视为 P3 完成。实现边界见 [SERVICE.md](SERVICE.md)。

### P4：手机、收费与按真实缺口扩展

在服务身份、工作接口与桌面体验稳定后做手机：新建/继续工作、读取公开分析、准确引用追问、阅读成果、分享材料；以 AC-25/26 验证桌面与手机接续。

准备收费时再接一个适合实际经营与分发渠道的支付服务，ycore 执行权益。按使用缺口增加 Google/Gemini 原生专项能力、更多供应商、平台收藏与数据、PDF/Office/音视频解析、更多导出格式、可信工具/MCP 和 Skill 包执行。支付与手机可以按实际发布需要分别推进，不互为强制前提。

不预先建设 Skill 市场、自动进化引擎、复杂推荐/知识图谱、IDE、剪辑器或无人值守发布系统。

## 5. 平台、格式和运行范围

| 范围 | 个人 Alpha | 后续 |
| --- | --- | --- |
| 平台 | 先在当前 Apple Silicon macOS 真机交付安装包；架构保留其他桌面系统能力，不宣称已支持 | Windows/Linux 分别做构建与真机验收；手机在 P4 |
| 输入 | 文本、Markdown/TXT、本地授权项目文件、ycore 返回的材料；链接可保存并保留实际读取范围 | 单篇网页正文、个人 RSS、平台授权、PDF/Office/音视频分别接解析与覆盖验证 |
| 输出 | Markdown 正文与可实际读取的导出文件；项目初始化按所选模板交付 | 图片、演示、PDF 等预览与真实导出逐项验证 |

网页正文能力未接通时，不把保存链接或 feed 正文标为已读全文。个人来源接入不要求购买服务，但不是把 ycore 管理来源 API 开放给普通客户端。

## 6. ycore 的当前配合项

**现在接入，不先扩平台：** 使用 v0.1.0 已有 sources/documents/changes 和 AI runs；客户端提交每次模型调用的独立关联 ID，保留产品运行到调用的映射。不同成员不是一次 ycore AI run 内的隐含角色。

优先处理三类真实阻塞：稳定 HTTPS 联调；客户端消费暴露的契约/错误问题；资料版本与模型输出的准确关联。TrendRadar 替代及来源可靠性由 ycore 自己收口，不把客户端开发绑在某个上游网站上。

当前不要求 ycore 新增团队 API、项目 API、雷达编辑 API、向量库或通用插件系统。当前 AI 契约没有原生工具调用、长研究、多模态或 JSON 取消接口；P1 以有界成员调用和本地获准工具完成协作，不能向用户展示这些尚不存在的模型能力。确有必要时，以具体客户端用例、契约测试和版本兼容说明驱动最小扩展。

P3 才提出身份/权益和可靠取消等具体服务缺口；产品运行模块所需私有存储、调度与恢复在 ytriple 中设计，复用托管组件，不默认改写 ycore 的治理边界。

## 7. 第一批实现任务与验收方式

实现已开始，原定接通顺序如下；实际完成证据与接续任务以 DELIVERY 为准：

1. 初始化可干净构建的桌面工程和持久工作对象；应用启动能保存、重开一份本地材料与草稿。
2. 接入 ycore 实际协议，在桌面验证材料与真实 AI；把同步、断流与未知付费状态一并做对。
3. 形成“首页开始 → 具体工作协作 → 返回并接续”的可操作路径，再进入 P1 的真实委派、证据异议和成果修订；雷达与项目独立页面按已确定逻辑接入真实业务。

每次交付提供可启动程序/安装包、实际操作路径、准确成果版本、测试与限制；增加 `docs/DELIVERY.md` 记录完成证据，不用本计划中的将来时充当进度。

测试重点是数据恢复、版本冲突、范围授权、付费调用幂等和连续操作。界面验收必须实际操作“开始 → 阅读分析 → 提修正 → 切换/停止 → 重开 → 使用成果”，不只截图或检查控件存在。模型质量使用真实样本人工审阅，并分开记录固定样本故障测试与真实模型证据。

P1 完成后再根据真实协作质量与返工量估算后续日期；当前不以缺少实现依据的周数承诺完整产品。首条可用工作路径必须处在完整产品页面结构中，能做完、改好、找回并交接；全套账户能力不阻塞这条路径。
