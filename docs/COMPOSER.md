# 对话入口：功能与状态

统一确认入口：[UI 与交互确认稿 v1](UI-BASELINE.md)。本文保留对应领域的详细规则。

2026-09-16。当前设计规格；实现覆盖与现场验证见 [交付记录](DELIVERY.md)。对象与执行规则继承 [INTERACTION.md](INTERACTION.md)，本文件定义底部输入的具体行为。目标是让用户直接开始或接续工作；常用操作图标化，必要身份与结果保留文字。

## 一个输入，四个常用操作

结构由上到下：一行当前工作、按需出现的引用材料、多行输入、底部工具行。没有材料时不留空槽。首页/项目的宽输入与沉浸决策面内的窄输入使用同一组件和状态；不并列多个输入框。

| 控件 | 常态外观 | 点击后的功能 |
| --- | --- | --- |
| 工作选择 | 新工作，或“脚本修订”及下拉箭头 | 查看归属、切换已有工作、开始另一项工作；先保存当前草稿，不迁移草稿到新对象 |
| 添加 | plus 图标 | 文件、粘贴链接、已有资料；次级分组可指定方法。选择只加入输入范围，不立即调用模型 |
| 交流对象 | users 图标 | 默认整个团队；可指定已有成员。选中成员时在输入上方显示“@核查员”等必要文字；不新建成员聊天 |
| 工作区展开 | panels-top-left 图标，始终直接可达 | 携带同一草稿展开决策/过程/结果；沉浸内改为收起图标并返回原入口；不发送或执行 |
| 发送 | arrow-up 图标，唯一实心主操作 | 提交当前文字、准备好的资料引用与明确交流对象；空输入禁用 |

这里的“四个操作”指工具行的添加、交流对象、工作区、发送。工作名称不是第五个工具按钮，而是避免发错上下文的必要身份。

不常驻模型列表、网络开关、角色人数、Skill 标签墙、自动匹配说明、三工作面名称解释或键盘教程。当前没有语音能力就不放麦克风。模型/团队/流程仍在各自设置中，不能借图标化把配置项全部塞进工具栏。

## 输入与引用

### 出现条件与草稿归属

首页默认常驻新工作输入；轻对话与沉浸决策面常驻当前工作输入。雷达列表、项目列表、资产列表、来源管理、定时管理和设置不常驻聊天框。雷达解读从正文末入口展开；项目概览先选工作或明确开始另一项；资料和资产先选引用去向。成果选段修订进入原工作。整版或选段的“让 AI 重新整理”把准确引用与整理要求加入该工作草稿，保留已有文字与交流对象；可先调整要求，发送后才执行。结果面不提供直接编辑、保存文件正文或手工合并入口。此规则优先于旧图中每页都放一个底部输入的表达。

同一视图只保留一个输入组件：阅读页的开展工作入口展开后由底部输入承接，不再并列第二个正文输入。关闭输入只收起视图并保存草稿；返回保留原文章、筛选和滚动位置。

未发送草稿按入口身份区分：首页新工作、某个项目新工作、某篇解读指定版本的新工作分别保存。再次进入同一入口恢复原草稿，不自动重复附加同一引用；切换入口不搬运文字或引用。首次发送建立工作后迁移为该工作的草稿身份，轻对话和沉浸视图共用它。用户明确开始另一项时才准备另一份草稿，已有未发送内容仍可找回。

### 文字与材料

- 首页初始身份为“新工作”；项目页明确为正在接续的工作；雷达提问显示新工作与文章引用；工作内部沿用同一身份。项目名称放在工作选择菜单中或必要的简短归属行，不重复整条导航。
- 新工作占位文字“交给团队一件事…”；已有工作为“继续这项工作…”。这只是空输入提示，不承载使用说明或伪造用户指令。
- 文件、资产和成果选段以紧凑条目显示名称，必要时带准确版本/范围，均可预览和移除。两条以内直接显示，更多收为“另 3 项”等可展开列表；不能只显示回形针而隐藏会被发送的对象。
- 添加文件先选取/本地解析；远端上传或读取能力与实际实现一致。待解析/失败状态保留名称和恢复操作，不能显示为已读全文。存在失败或未就绪材料时先修复或移除，再提交，不能静默漏传。
- 仅有附件、没有目标时不自动分析；发送暂不可用，焦点提示“写下想让团队做的事”。不弹配置向导。
- 从结果选段带入时显示“脚本 v4 · 第二段”；正文与版本不可悄悄换为最新。点击引用可回看原位置，移除引用不删除原成果。
- 选段引用成功后让原工作输入可见并聚焦，保留此前未发送的文字；如果无法准确映射选段，说明原因，不退化为整篇引用。材料预览允许明确缩小范围或恢复完整已读范围，不能把未读正文算作已选内容。
- 输入长文自动增高至合理上限，然后内部滚动；工具行固定在输入底部，页面预留真实底部空间。材料很多时滚动材料区，不挤掉输入与发送。

## 发送、处理中补充与停止

| 状态 | 主操作及旁边内容 | 执行规则 |
| --- | --- | --- |
| 空草稿 | 灰色发送箭头；工作区图标仍可用 | 展开仅携带草稿，不创建永久空工作 |
| 可发送 | 实心箭头，悬停提示“发送”及快捷键 | 提交身份持久化；双击或重复快捷键只接受一次 |
| 提交中 | 原位置进度指示，暂不可重复发送 | 输入快照保留；结果未知先核对，不换新身份重试 |
| 团队处理中，输入为空 | 发送位置变为停止方块；简短“处理中” | 停止针对当轮，取消未确认时显示停止中，不假称已停止 |
| 团队处理中，写了补充 | 停止方块与发送箭头并列；箭头旁仅“下一轮” | 点击才把补充加入待发队列，不中断/改写当前轮，不同时运行两轮 |
| 已有待发补充 | “待发 1”可展开编辑或撤回 | 当轮成功且未等待用户、未停止、未失败才按顺序发送；异常时保留待发、由用户明确继续 |
| 团队等待用户答复 | 提示具体问题；发送为“回答并继续”的图标提示 | 答复绑定原待决及版本；在同一个底部入口显示问题与可选方向，点击选项只准备可改写的答复，明确发送后续接原运行，不塞入普通补充队列 |
| 发送失败 | 原草稿与引用保留，短错误和重试操作 | 先查询同一提交状态；确认失败后重试，不复制工作或付费调用 |
| 服务不可用 | 保留可编辑输入与展开；简短“连接服务”恢复入口 | 历史可读；连接返回同一草稿，不把草稿自动发送 |

用户点停止会同时暂停自动发送待发补充，但不删除补充；明确继续后才恢复。单纯关闭视图不停止已授权运行或已明确加入的补充；退出整个应用能否继续取决于实际执行位置，本机模式不承诺关闭后后台续跑。用户切换到其他工作时，待发补充仍绑定原工作，不进入当前可见输入。

队列不是首屏新模块：仅在用户实际提交了下一轮补充后出现。初期实现若暂不支持排队，应保留编辑草稿并明确当前不能提交补充，不展示虚假的已排队状态。

### 待发编辑的边界

- 打开待发编辑前核对该提交尚未开始执行；进入编辑时暂停该工作的自动续发，当前轮继续处理。
- 编辑草稿独立保存，关闭弹层仍可找回；主输入中的另一个草稿不受影响。保存更新同一待发提交，不复制消息或运行；放弃只丢弃这次编辑，撤回才移除待发提交。
- 保存或放弃编辑后仍保持队列暂停，明确“继续待发”才恢复；存在未处理的编辑草稿时先完成或放弃，避免发送旧内容。
- 待发提交使用提交时的团队与流程快照。编辑可以改变目标、可用材料和原搭配中的交流对象，不因全局配置更新自动换人或换流程。

## 键盘、焦点与图标可识别性

- 默认 Enter 换行，macOS Cmd+Enter / 其他桌面 Ctrl+Enter 发送；输入法合成中不发送。快捷键在发送的 tooltip 和帮助中展示，不常驻占一整行。
- Tab 顺序与视觉一致；每个图标有可访问名称，悬停和键盘聚焦都显示短 tooltip。菜单有文字选项，图标化不等于让用户猜菜单含义。
- Esc 先关闭菜单/材料预览，不清空草稿、不停止任务。关闭弹层回到原控件；选材料后回输入继续写。
- 拖放资料、粘贴链接与加号入口走同一资料状态机，不各自建立上传或授权规则。
- 常用图标 18–20px，点击区至少约 40–44px；当前工作文字约 13px，输入正文 15–16px。窄面减少间距或折叠材料，不能把点击目标和文字无限缩小。
- 工作区图标与发送相邻但独立，尺寸不低于其他操作。初次悬停/聚焦说明“展开团队工作区”；不靠持续闪烁、亮色竖条或长按钮文案增强存在感。

## 视觉与验证

输入只保留一个轻边界和干净表面。没有左侧亮条、彩色提示卡、装饰闪光或叠层胶囊；操作图标中性，只有可执行发送强调。状态不能只靠颜色。必要的工作名、引用、下一轮与错误文字保留，普通操作不在图标旁重复写名称。

至少验证：新建/接续不混淆；未发送展开后返回不丢输入；选段版本保持；移除失败附件后可发送；中文输入法与快捷键；重复发送；运行中补充排队/编辑/撤回；停止和失败不自动发下一轮；等待答复准确接续；切工作不串草稿；窄面不遮内容。静态状态稿不证明上述行为已经实现。


### 待决答复的持久化与恢复

当前文字答复使用独立草稿，普通目标草稿保留；待决解决或停止后恢复普通输入。关闭工作区、切页或退出不代表回答，也不代表取消。问题记录所属工作、运行、成果基准版本和提出它的成员步骤；改变团队搭配不改写等待中的快照。

“回答并继续”原子记录一次答复，恢复提出问题的步骤，已完成的前序步骤不重跑；后续已排队补充仍暂停，由“继续待发”明确接续。重复提交同一答复不重跑；被回答、撤回或版本已过时的问题不能接收新的答案。停止等待保留答复草稿和历史过程。当前答复支持选项和自由文本；待决内补附件、按条件更新问题及稍后提醒仍需扩展，不冒充已实现。

## 过程追问与复盘输入（2026-09-17 已接通）

过程记录的追问按钮把当时成员、轮次、任务、公开内容和来源范围保存为准确快照，带回同一工作的底部输入。可选择连续选段；格式边界无法准确对应时明确要求重选，不悄悄扩大为全文。只是准备草稿，不立即调用模型。

输入条显示本轮“解释与追问 / 过程总结 / 工作复盘”用途。追问的回答进入交流记录，不发布主成果新版本；总结与复盘各自生成支持成果。过程操作保留已有用户文字、其他材料和交流对象；切换另一过程操作时，仅替换上次由该入口自动加入的请求和引用。用户移除该引用后不继续把它当作自动准备内容。明确发送的运行保存输出用途，排队和重启不变。
