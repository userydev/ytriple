# 抖音收藏接入验证

验证日期：2026-09-11。基于用户已登录的 Codex 浏览器进行页面小样检查，并在 Chrome 开发者工具中检查网站正常发出的收藏请求与 JSON 预览；未提取或导出登录凭据，未自行构造接口请求，未下载媒体，未修改收藏。记录技术观察，不保存用户账号标识或收藏明细。

## 结论

正常登录后，通过网页 DOM 读取收藏列表并驱动滚动加载的路线已得到小样验证。这只证明资料可达；正式采集应优先验证结构化 JSON 的批量读取，DOM 作为备用。采集由确定性代码执行，AI 在取得材料后负责消化，不逐条操纵网页。

**Chrome 中已验证收藏批量 JSON 确实可取得。** 网站正常请求返回 `aweme_list`、`cursor`、`has_more`，请求体使用 `count` 和 `cursor`。这使结构化批量采集有了当前账号的实际证据；程序采集、直接分页重放及全量导入仍未完成。

当前 Codex 与 Chrome 的浏览器自动化接口均未提供网络响应体读取能力；本次通过 Chrome 原生开发者工具查看响应，属于一次性技术验证。产品需要自己的程序采集通道，不能把开发者工具界面操作当作日常采集流程。

## 建议的接入方式

1. **浏览器会话**：用户在采集器使用的浏览器中正常登录。Playwright 的专用持久上下文可保留该会话；使用独立目录，不从 Codex 或日常 Chrome 复制凭据或主用户目录。[持久上下文说明](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context)
2. **结构化数据采集**：先识别收藏页真实发出的请求、响应字段与分页条件，优先验证会话内批量分页请求。共享会话可保留身份，但修改分页游标后是否仍有有效签名需实测；Playwright 的请求接口不会替网站执行签名代码。若直接分页不能稳定使用，则监听网站正常加载收藏时返回的 JSON，让站点完成请求与签名，再整批提取；DOM 读取仅作为备用。[请求接口](https://playwright.dev/docs/api/class-apirequestcontext#api-request-context-fetch)、[JSON 响应读取](https://playwright.dev/docs/api/class-response#response-json)
3. **资料整理**：将作品 ID、类型、原链接、页面描述、封面引用和观察时间交给 ytriple，进入主题整理与 Lib。未取得的收藏时间、正文或字幕保持缺失，不用观察时间代替收藏时间。
4. **内容补全**：需要深入理解时再访问详情；对授权范围内可取得的图文与视频材料，另行验证图像识别、语音转录或多模态理解。记录每次结论实际使用的是描述、画面、转录还是完整材料。

首版采集由前台任务启动，用户能看到进度、停止并在以后继续。分页中断或本次未出现的条目不自动视为取消收藏。当前没有验证大量历史、长期登录稳定性、批量详情读取及媒体内容补全，这些需在接入阶段继续验证。

两种网络路线都按响应批次处理、按作品 ID 去重并保存进度，无需逐条打开视频，也不让模型参与每次翻页判断。直接分页的吞吐、平台限制与签名有效期以实际验证为准，不承诺仅凭登录即可无限批量抓取。

若后续希望直接从用户日常浏览器发起导入，可增加浏览器扩展：Chrome 的 `activeTab` 与 `scripting` 支持用户触发的页面访问，扩展可通过 Native Messaging 与本机应用通信。它是后续可选入口，尚未在本次安装或测试。[页面访问](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)、[本机通信](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)

扩展的普通 `webRequest` 接口不直接提供响应体，不能把监听响应头当成取得收藏 JSON；若采用扩展路线，响应体获取方式需另行设计与验证。[Chrome webRequest](https://developer.chrome.com/docs/extensions/reference/api/webRequest)
