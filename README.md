# ytriple

**Y is the user. Triple is the amplifier.**

ytriple 是以用户为中心的 Local-first AI Workbench，通过一支真正协作的常驻最小 AI 团队，整合本地工具、文档、知识和外部资源，放大个人能力。

## 当前起点

按用户 2026-09-11 确认，从零、从文档重新开发。不以旧实现、旧架构、旧 PRD 工作流或旧文档作为兼容与参考基线。即使某个工作区仍有历史文件，也不改变这一方向；不将历史原型能力当作新产品的已完成能力。

## 两份主要正文

- [讨论总结](docs/讨论总结.md)：已确认定位、常驻团队、职责边界、当前重心与长期目标。
- [产品调研](docs/产品调研.md)：竞品与实现产品所需的能力、模型、Agent、工具、浏览器辅助、平台数据及服务器服务参考；不是开发规格。

专项参考：[团队协作与交互调研](docs/参考/团队协作与交互调研.md)，研究常驻成员协作、子 Agent 扩展和用户围绕说明书工作的交互。属于产品与能力研究，不是已选定的框架或工程实施要求。

## 产品边界

核心团队为统筹 / 工作伙伴、CTO / 产品技术伙伴、Deep Research / 研究员。用户可以面对团队，也可以直接与一个成员工作；固定身份不等于每次全员运行或只能三个 Agent。

项目能力以初始化、监控和指定文档反馈为主；项目代码与正式开发方案的修改继续交给 Codex。研究、文档和资料组织是工作台自身的重要能力。

基础模型接入以 OpenAI 兼容格式为主，同时允许 Google/Gemini 原生能力，包括 Deep Research。账号监控先关注 TikTok、YouTube、X、抖音，必要时研究浏览器插件等辅助方式，在本机自用雏形上逐步加入。

长期方向是开源本地工作台，以及可自部署、可选订阅托管的服务器能力；具体收费服务尚未确定，当前不执行仓库公开或发布。

## 研发协作

用户决定目标、取舍与授权。网页 ChatGPT 维护讨论总结、产品与能力调研及参考；Codex 负责具体设计、选型、开发拆解、实现与验证。研究不自动成为需求，不由网页 AI 另建工程规格或实施路线。
