**Y is the user. Triple is the amplifier.**

ytriple 是以用户为中心的 Local-first Personal AI Workbench。Y 与真正协作的常驻 AI 团队共同吸收，沉淀本地 Lib 资产，产出给人和工具的有效说明书，再通过实际使用、项目反馈和经验复用共同成长。

**吸收 → 本地资产 → 两类说明书 → 人与工具使用 → 真实反馈与成长。** 团队协作和交互贯穿全程，雷达、研究、文档、工具和项目是服务这条主线的能力与入口，不是互相独立的产品。

## 本地运行

当前已有可运行的 **0.1 开发版**：真实团队协作、应用内三面板工作台、MD/HTML 修订与继续加工、本地 Lib 收藏和跨任务复用、常用文档文字导入、PNG/PPTX 导出，以及本机 AI 体系与项目初始化。Google 专项 Agent 已接入；平台收藏采集与 Radar 仍待实现，这不是完整首版发布。

使用 Node.js 24 或更新版本：

```sh
npm ci
npm run dev
```

`npm run dev` 构建并打开 Electron 工作台；修改代码后重新启动。`npm run build` 构建，`npm start` 启动已有构建。首轮使用已实测的 Gemini；从侧栏“设置 → AI 模型”配置渠道并测试连接，从“Agent 团队”分配成员模型、职责和协作方式。

在同一个应用窗口内，左侧是对话与决策，右侧上下分别是 Agent 过程与成果；可拖动内部分隔线调整比例，各面板支持折叠、展开、放大与还原，也可切换专注决策布局。右侧另有“上下 / 过程 / 成果”三种模式，单独看过程或成果时左侧决策保持可见。三个面板跟随同一任务。决策区承担团队会议汇报：直接读到基本结论、关键依据、取舍和需要 Y 决定的事项；较长附件通过“查看完整内容”进入右侧，原文可保存为文档。过程分为“思路摘要 / 资料与网站 / 成员对话 / 执行记录”；问题理解、核查方法、依据发现、方案取舍和判断说明可分层展开，网站区显示实际检索词、链接和读取状态，可查看当前目标全部过程或本次处理。只展示成员明确汇报的公开分析、提供商公开摘要与真实协作回复。公开过程可整理为 MD 文档，继续编辑并收藏。成果目录按文档、图片与演示文稿分组，可搜索并查看版本。Markdown 支持常用公式、脚注、标题锚点、表格内换行与宽表格。成果可直接修改或交给团队继续修订，保存和加工期间保护草稿并阻止重复提交；收藏到 Lib 后可编辑并作为另一项工作的资料。

侧栏可固定，展开时为内容让出空间；最近工作可重命名、归档或永久删除，只有归档可恢复。删除停止执行并清除会话、过程和恢复记录，已保存的独立成果文件、Lib 与项目文件保留；旧版“最近删除”也按此规则清理。设置收为一个可折叠菜单，内含 AI 模型、Agent 团队、本机设置三个入口，切换页面和连接时保留各自配置草稿；未保存的密钥只留在当前应用内存。连接页直接测试文本、工具与流式能力，区分未配置、未测试、通过和失败，测试结果按实际连接保存；仅修改名称不会丢失验证。成果常用编辑与继续加工直接可见，导出和收藏/版本/文件位置分别归入“导出”“管理”。成员可修改角色提示词、回答详略与自动协作方式；Google 目录可独立添加 Gemini、Deep Research、Deep Research Max、Antigravity 连接。专项 Agent 使用官方 Interactions 接口，Deep Research 的公开分析摘要实时回到过程区，断线后按原任务续接，文本报告保存到本地；Deep Research 与 Antigravity 已分别完成真实合成调用，Max 预设尚未单独实测。

项目页采用左侧项目/文件树、中间查看、右侧决策的 IDE 布局，两条分隔线可独立调整并保留宽度。项目合并中央登记与 Code 实际目录，同一项目的 main/dev/task 可切换浏览；支持常见文本/代码与 Markdown 正文、相对文档链接，跳过隐藏、依赖及凭据文件。多个项目可独立展开，支持方向键导航、收起全部、定位当前文件、重新读取及失败重试；收起树或决策面板保留当前预览与讨论草稿。只有发送时才创建并运行讨论，发送带入扫描概况；预览正文不会自动发送，需作为资料添加。已有项目讨论显示“查看项目”，新项目在项目页或项目孵化讨论中创建，重复初始化会被拦截。应用运行期间默认每 30 秒只读刷新本地状态，可暂停或手动刷新。

任务状态与会话保存在系统应用数据目录（macOS 为 `~/Library/Application Support/ytriple`），成果默认在 `~/AI/knowledge/workspaces`，明确收藏的可复用副本保存在 `~/AI/knowledge/lib`，保留原成果来源和各自版本。AI/Code/成果根目录可以配置；项目正式文档在对应项目的 main/dev 目录。界面输入的密钥由系统凭据保护能力加密保存，也可使用已有环境变量，密钥不进入仓库或任务快照。

```sh
npm run typecheck
npm test
npm run smoke
npm run probe -- gemini --team
```

前三项为本地验证，`smoke` 只写临时目录。`probe` 会使用指定渠道做少量真实模型调用；`--team` 追加合成团队任务。实际状态、验收范围和待办见 [开发计划](docs/开发计划.md)。

## 此版本的实现范围

第一版同时包含以下四部分，以 AI 与多 Agent 底座为核心：

- **AI 与多 Agent 底座**：真实模型与工具调用、成员委派与追问、必要上下文共享、成果交接，以及工作中断后的接续。
- **AI 工作台基本功能**：团队交流与成员直聊、工作和项目组织、资料与成果查看、历史接续、模型及工具配置。
- **项目初始化**：从产品雏形、需求讨论到 Codex 可以接手开发的环境，遵循本机 `/Users/Admin/AI` 下的文档与项目管理规则，建立项目登记、规则、必要文档和适用的 Git/worktree。缺少本机 AI 目录与规则体系时，先实际创建完整体系，再初始化项目；已有体系读取并保留。这两种环境都属于首版必验收范围。其他机器默认使用当前用户的 `~/AI`，具体根路径可配置；文档随实际工作持续改进。
- **文档与成果处理**：主要通过多 Agent 交互完成读取、分析、撰写、修订和保存。以 MD 输出为主，输入覆盖 PDF、TXT、MD、JSON、DOC/DOCX 等常规文档，产出也包含信息图和 PPT。

底座与项目初始化、信息消化、文档产出等真实流程同步建设和验证，工作台承载完整体验。工程选型、实施增量和验收见 [开发计划](docs/开发计划.md)，由 Codex 维护；基础雷达与收藏消化按当前产品重心设计，入口覆盖、Radar 深度、账号监控、浏览器辅助和服务器能力逐步扩展。

当前场景整合为项目孵化、信息吸收与学习、研究与创意产出三条相连的工作流。首批资料入口关注知乎收藏、抖音收藏或视频链接、GitHub，以及 X 信息；同时提供通用信息源，经团队消化后形成符合产品主线的推荐。具体接入工具及验证状态见产品调研。

团队平时保留入口，明确交给 ytriple 的任务完整展示。主面板像团队向 Y 汇报的会议区，结论与基本依据完整可读，右侧两个辅助面板按需展示详细分析、报告、证据与成果，始终位于同一个产品窗口内。模糊问题主要由团队判断推进，Y 的明确否定与修正优先。首版只做前台运行，保存工作便于下次接续；暂不设置任务总时长和费用预算，保留可配置限制与资料外发控制的扩展方式。

## 产品边界

核心团队为统筹 / 工作伙伴、CTO / 产品技术伙伴、Deep Research / 研究员。用户可以面对团队，也可以直接与一个成员工作；常驻成员可按需调用子 Agent，固定身份不等于每次全员运行或只能三个 Agent。

雷达既消化积压收藏，也处理预置与手动信息源，用户主要阅读团队整理后的主题知识与能力线索，必要时回到原文。工具与工作流吸收进入本地资产，候选和已验证状态区分。信息源与个性化消化可成为独立工具或订阅服务方向，不只是新闻推送。

项目能力以初始化、监控和指定文档反馈为主；项目代码与正式开发方案的修改继续交给 Codex。研究、文档和资料组织是工作台自身的重要能力。说明书既包括直接成果和指导方案，也包括给执行者的目标、方法与条件；不强制生成两套重复文档。

基础模型接入以 OpenAI 兼容格式为主，同时允许 Google/Gemini 原生能力，包括 Deep Research。首版支持 Gemini、DeepSeek 与本机 Ark 的多套连接配置，可按成员选择并在任务中覆盖；具体模型能力与连接状态分别验证。账号监控先关注 TikTok、YouTube、X、抖音，必要时研究浏览器插件等辅助方式，在本机自用雏形上逐步加入。不要求全部吸收入口或平台一次开发完成。

长期方向是开源本地工作台，以及可自部署、可选订阅托管的服务器能力；具体收费服务尚未确定，当前不执行仓库公开或发布。成长由说明书的实际用途、Y 与团队的能力改善和真实项目反馈检验；高度自动化依靠验证过的资产与明确授权逐步形成。

## 研发协作

用户决定目标、取舍与授权。网页 ChatGPT 维护讨论总结、产品与能力调研及参考；Codex 负责具体设计、选型、开发拆解、实现与验证。研究不自动成为需求，不由网页 AI 另建工程规格或实施路线。
