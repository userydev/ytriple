# ytriple

**Y is the user. Triple is the amplifier.**

ytriple 是以用户为中心的 Local-first Personal AI Workbench。Y 与真正协作的常驻 AI 团队共同吸收，沉淀本地 Lib 资产，产出给人和工具的有效说明书，再通过实际使用、项目反馈和经验复用共同成长。

**吸收 → 本地资产 → 两类说明书 → 人与工具使用 → 真实反馈与成长。**团队协作和交互贯穿全程，雷达、研究、文档、工具和项目是服务这条主线的能力与入口，不是互相独立的产品。

## 当前起点

按用户 2026-09-11 确认，从零、从文档重新开发。不以旧实现、旧架构、旧 PRD 工作流或旧文档作为兼容与参考基线。即使某个工作区仍有历史文件，也不改变这一方向；不将历史原型能力当作新产品的已完成能力。

## 两份主要正文

- [讨论总结](docs/讨论总结.md)：已确认的吸收与产出主线、两类说明书、Lib、团队、项目反馈、七层成熟度和长期目标。
- [产品调研](docs/产品调研.md)：竞品与实现产品所需的能力、模型、Agent、工具、浏览器辅助、平台数据及服务器服务参考；不是开发规格。

专项参考：[团队协作与交互调研](docs/参考/团队协作与交互调研.md)，研究常驻成员协作、子 Agent 扩展和用户围绕说明书工作的交互。属于产品与能力研究，不是已选定的框架或工程实施要求。

## 产品边界

核心团队为统筹 / 工作伙伴、CTO / 产品技术伙伴、Deep Research / 研究员。用户可以面对团队，也可以直接与一个成员工作；常驻成员可按需调用子 Agent，固定身份不等于每次全员运行或只能三个 Agent。

雷达既消化积压收藏，也处理预置与手动信息源，用户主要阅读团队整理后的主题知识与能力线索，必要时回到原文。工具与工作流吸收进入本地资产，候选和已验证状态区分。信息源与个性化消化可成为独立工具或订阅服务方向，不只是新闻推送。

项目能力以初始化、监控和指定文档反馈为主；项目代码与正式开发方案的修改继续交给 Codex。研究、文档和资料组织是工作台自身的重要能力。说明书既包括直接成果和指导方案，也包括给执行者的目标、方法与条件；不强制生成两套重复文档。

基础模型接入以 OpenAI 兼容格式为主，同时允许 Google/Gemini 原生能力，包括 Deep Research。账号监控先关注 TikTok、YouTube、X、抖音，必要时研究浏览器插件等辅助方式，在本机自用雏形上逐步加入。不要求全部吸收入口或平台一次开发完成。

长期方向是开源本地工作台，以及可自部署、可选订阅托管的服务器能力；具体收费服务尚未确定，当前不执行仓库公开或发布。成长由说明书的实际用途、Y 与团队的能力改善和真实项目反馈检验；高度自动化依靠验证过的资产与明确授权逐步形成。

## 研发协作

用户决定目标、取舍与授权。网页 ChatGPT 维护讨论总结、产品与能力调研及参考；Codex 负责具体设计、选型、开发拆解、实现与验证。研究不自动成为需求，不由网页 AI 另建工程规格或实施路线。
