## 产品结构

客户端直接面向用户，共享一套可视化团队工作空间：

- **雷达**：栏目式解读、来源选择与积压收藏消化，连接理解、证据和资产，不只是新闻摘要。
- **项目**：软件项目的初始化、状态与指定文档反馈；媒体项目的频道、作品、脚本、制作说明和复盘。
- **资产**：知识、说明书、Skills、工具与工作流的来源、版本、使用和验证。

**Skill 是可实际调用的能力，不是角色改名。**成员有不同的默认职责，按需委派和追问，也可以调用子 Agent。用户可以指定方法，团队也可以在已启用和授权范围内自动选择；实际加载、工具执行、成果与验证分开显示。

**例行工作**把有效委托变成按时间、变化或实际节点触发的工作，关联原项目和资产。待处理视图收敛判断与成果；反馈整理、轻量交付检查及方便的资料导入/导出辅助完成真实工作，不另造企业任务平台。

服务器分为 **信息服务、AI 能力服务、用户服务**。用户可以订阅官方能力而无需配置各家 API，也可使用自带 API 或自部署服务。托管任务只使用实际获准的资料与工具，不自动获得本机文件或浏览器登录态。订阅和本地资产所有权分开。

## 现有开发版与运行

当前开发版已接入软件与媒体两条工作路径：项目初始化/已有目录导入，频道与多版本作品，主编/研究员/内容编辑协作，方法导入与实际调用，版本交接与独立检查，反馈整理，本机与远端例行，以及关联资产备份恢复。

- 打开应用先进入「工作台」，从目标开始或继续已有工作；待我处理、交付与反馈、例行工作集中在这里。已有任务不会在启动时自动打开或运行。
- 进入具体工作后，交流、分析过程与成果可同时对照；可切换两面协作、分别聚焦和调整空间，窄窗口同级切换。项目直接进入完整工作区。分析过程保留公开判断、依据和修正，可总结得失并回到原文与版本。
- 在「项目」选择软件或媒体；媒体从少量频道背景和材料开始，作品的选题、脚本、制作说明、发布准备和反馈保持关联。
- 在「资产 → Skills」查看七项内置方法，也可以导入可信包/链接、编辑副本、指定成员范围。当前工作可选择自动、指定或不用；过程保留实际加载版本，试用与验证分开。
- 从成果的「交接与反馈」登记接收方、版本、缺口和标准，执行独立就绪检查；登记真实接收/使用证据，整理反馈并回到原工作。软件反馈只写专用文档。
- 在「雷达 → 平台与收藏」或「资产 → 导入资料 / 备份与恢复」消化成批材料；无信息服务也可读取公开网页。备份恢复使用新副本，保留关联且不带出密钥。
- 有效工作可设为本机例行；设置中明确启用后，关闭窗口仍可由菜单栏后台处理。连接独立工作服务后，还可在原工作里委托远端处理选定材料，退出桌面不停止远端进程。
- 「工作台 → 待我处理」聚合真实受阻、成果和反馈，可暂缓或调整通知；交付列表区分计划日期与实际发布。

实现范围、真实 Gemini 合成验收及边界见[当前实现与验证](docs/开发计划.md)。脚本/说明书形成、接收方检查、实际制作和用户效果分别记录。

当前工程使用 Node.js 24 或更新版本，Electron + React + TypeScript。依赖由锁文件固定：

```sh
npm ci
npm run dev
```

`npm run dev` 构建并启动桌面应用，修改代码后重新启动；`npm run build` 构建，`npm start` 启动已有构建。当前模型入口在设置中，模型连接与成员配置按实际版本使用。模型设置支持自带 API，或登录已配置的自部署工作服务使用统一模型；官方运营套餐与支付尚未开放。

```sh
npm run typecheck
npm test
npm run smoke
npm run probe -- gemini --team
npm run probe:product
npx tsx scripts/probe-work-service.ts
```

前几项用于本地检查，`smoke` 只写临时目录。`probe` 会使用获准凭据发起真实模型调用，不能与替身测试混计，也不要为检查文档自动运行。模型、资料覆盖、导出质量与桌面交互分别验证。

雷达的独立信息服务可另用 `npm run source:up` 启动（需要 Docker/OrbStack），再从雷达的信息源管理连接。服务配置与实际覆盖见[服务说明](services/source-service/README.md)。本地资料、成果和 Skill 不以该服务启动为前提。

独立 AI / 用户 / 委托服务通过 `npm run work:serve` 启动，默认 `http://127.0.0.1:8788`；服务管理员配置实际模型、账号和权益，桌面在「AI 模型 → 账户与能力服务」登录。密钥留在服务器，用户无需逐家填写 API。安装和账户创建步骤见[工作服务说明](services/work-service/README.md)。它支持自部署，不代表已经开通官方商用订阅。

现有默认任务状态保存在系统应用数据目录；成果在 `~/AI/knowledge/workspaces`，明确收藏的可复用副本在 `~/AI/knowledge/lib`。AI、Code 和成果根路径可配置；项目权威文档跟随项目。新文档不授权迁移或覆盖当前用户的数据、规则、登录态或密钥。

## 协作边界

用户决定目标、取舍与授权；网页 ChatGPT 维护产品定义、能力研究和方案审视；Codex 维护具体设计、工程计划、实现与验证。产品文档说明入口、操作、结果与不算完成的情况，不指定技术架构和开发排期。

正在开发的项目由 Codex 等工具负责实际工程修改；ytriple 负责初始化、监控和指定反馈。设计、剪辑和发布继续使用专业工具。例行任务默认不增加改代码、发布、删除或安装权限。
